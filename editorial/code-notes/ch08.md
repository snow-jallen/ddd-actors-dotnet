## ch08-s01: Domain events as facts experts care about

**Files**

- `src/Ohmline.SharedKernel/Identity/CommandId.cs` (new, 29 lines): `readonly record struct CommandId :
  IValueObject<CommandId, Guid>`, the same shape as `SessionId`/`JourneyId` (version 7 guard in the
  `field` init, `New(TimeProvider)`, `TryCreate`). Summary: "a command that is sent twice (a retry
  after a timeout) carries the same id both times. Every event a command causes records this id: it
  is the event's causation."
- **Commands:** every command base gained `CommandId` as its **first positional member**, and every
  leaf passes it on: `public closed record SessionCommand(CommandId CommandId, SessionId SessionId);`,
  `ChargePointCommand(CommandId, ChargePointId)` (and the closed intermediate `ConnectorCommand(CommandId,
  ChargePointId, int ConnectorNumber)`), `SitePowerBudgetCommand(CommandId, SiteId)`. Files:
  `src/Charging/Ohmline.Charging.Contracts/ChargePoints/ChargePointCommand.cs`,
  `.../Sessions/SessionCommand.cs`, `src/SiteEnergy/Ohmline.SiteEnergy.Contracts/Budgets/SitePowerBudgetCommand.cs`.
  Positional, so no command can be built without an id (the sender gives it).
- **Events:** each event base gained a body with two `init` properties (quote it from
  `src/Charging/Ohmline.Charging.Domain/Sessions/SessionEvent.cs`, lines 13–20 at this tag):

  ```text
  public closed record SessionEvent(SessionId SessionId)
  {
      /// <summary>The command that caused this event: its causation.</summary>
      public CommandId CommandId { get; init; }

      /// <summary>When it happened: the time of the decision, from its context.</summary>
      public DateTimeOffset OccurredAt { get; init; }
  }
  ```

  The same body is in `ChargePointEvent.cs` and `SitePowerBudgetEvent.cs`.
- **The per-event times went into the base:** `SessionStarted.StartedAt`, `ChargingSuspended.SuspendedAt`,
  `ChargingResumed.ResumedAt` and `SessionEnded.EndedAt` are gone; Evolve reads `OccurredAt`
  (`MeterReading.FromWattHours(started.MeterStartWh, started.OccurredAt)`, `new Suspended(..., suspended.OccurredAt)`,
  `new Ended(..., ended.OccurredAt)`). `MeterValueRecorded` keeps `MeasuredAt` and its summary now
  says why: "It has two times: when the charge point measured it, and when Ohmline recorded it
  (`OccurredAt`)." `ConnectorReserved.ExpiresAt` stays (it is a decision, not a timestamp). Good
  material for "decision inputs rather than state dumps".
- **The deciders stamp once.** In each of `ChargePoint.cs`, `ChargingSession.cs` and
  `SitePowerBudget.cs` the old public table became `private static ... DecisionTable(...)` and the new
  public `Decide` is one line (ChargePoint, lines 26–32):

  ```text
  public static Result<ImmutableArray<ChargePointEvent>, ChargePointError> Decide(
      ChargePointState state, ChargePointCommand command, DecisionContext context) =>
      DecisionTable(state, command, context).Map(events => Stamp(events, command, context));
  ```

  with `Stamp` (ChargePoint line 146, ChargingSession line 148, SitePowerBudget line 166):
  `[.. events.Select(@event => @event with { CommandId = command.CommandId, OccurredAt = context.Now })]`.
  The summary: "The table says what happened; the stamp says why and when." `with` on the closed base
  type works (the virtual clone keeps the leaf type). The session table no longer needs the context
  for times (`Start(start)`, `End(terms, meter)` lost their `context` parameter); the charge point
  table still does (`ReservationHold`, `HasExpiredAt`). The site power budget's `DecisionTable` takes no
  context at all.
- Tests: `tests/Ohmline.Charging.Domain.Tests/Known.cs` gained `Command` (one fixed `CommandId` for
  every test command; the summary says why one is enough); `tests/Ohmline.Charging.Domain.Tests/Stamps.cs`

  `TheDepot.cs` (Site Energy tests) has the same `Command` and `At`. Every test command now starts with
  `Command`, and every expected event has `.At(...)`: this is most of the diff's line count.

## ch08-s03: Domain services: the price calculator

**Files** (`src/Tariffs/Ohmline.Tariffs.Domain/Pricing/`, namespace `Ohmline.Tariffs.Domain.Pricing`)

- `MeteredInterval.cs`: `readonly record struct MeteredInterval(from, until, Energy)` with a guard
  ("An interval ends after it starts") and `Length`.
- `SessionUsage.cs`: `sealed record SessionUsage(ImmutableArray<MeteredInterval> Intervals, TimeSpan
  Idle)` with `Energy` (sum) and value equality. `Idle` is "how long the car stayed plugged in after
  it stopped charging".
- `PriceLine.cs` (closed hierarchy, quote whole): `closed record PriceLine(Money Amount)`;
  `EnergyCharge(TimeOfUseBand? Band, Energy Energy, Money Rate, Money Amount)`, `TimeCharge(TimeOfUseBand?
  Band, TimeSpan Duration, Money Rate, Money Amount)`, `SessionFeeCharge(Money Amount)`,
  `IdleFeeCharge(int Minutes, Money Rate, Money Amount)`, `PriceCapApplied(Money Cap, Money Amount)`
  (a negative amount).
- **`PriceBreakdown.cs` (quote whole):** `sealed record PriceBreakdown(Currency Currency,
  ImmutableArray<PriceLine> Lines)` with **`Total` computed as the sum of the lines**: "so a breakdown
  always adds up to its total to the cent". (Supple design: an assertion made structural.)
- **`PriceCalculator.cs`** (`public static class`; quote from `ch08-s07` for the final shape, the
  only change in 8.7 is the band lookup):
  - the class summary is the section's thesis: "a pure function of the data it is given. It reads no
    clock, asks no tariff book and calls no service: whoever needs a price brings the tariff snapshot
    and the usage".
  - `Price(TariffSnapshot, SessionUsage)` (line 23 at `ch08-s07`): portions per interval, then one
    line per component **in the tariff's order**, each rounded once (`line with { Amount =
    tariff.Rounding.Round(line.Amount) }`: `with` on the closed base), then `Capped`.
  - `Lines(...)` (line 36): a switch over the closed `TariffComponent`, no discard; uses `is var kWh
    and > 0m` to skip empty lines; idle minutes are whole minutes after the grace period.
  - `Capped` (line 57): adds `PriceCapApplied(cap, cap - total)` when the total is above the cap.
  - `Portions` (line 70) and `MinutesOf` (line 92): an interval is cut at every whole UTC minute, each
    piece is placed in its band by its local time, pieces are grouped by (energy rate, time rate),
    and the interval's energy is shared in proportion to time (`kWh * length.Ticks /
    interval.Length.Ticks`), so an interval that stays in one band keeps its energy exactly.
  - `RateAt<TRate>` (line 106): "The rate whose band holds the time, else the one without a band, or
    none."

**The primer's numbers come out exactly** (quote `Given_the_primers_charge_then_it_costs_16_dollars_59`):
27.6 kWh at USD 0.42 = USD 11.59 (11.592 rounded), USD 1.00 session fee, 10 idle minutes (25 minus 15)
at USD 0.40 = USD 4.00, total USD 16.59, as in `docs/ohmline-primer.md` step 10.

## Deviations from the outline (and why)

1. **`TariffComponent` is a closed record hierarchy, not a union** (8.2). A tariff is copied into
   `SessionStarted` (persisted) and will be published by the tariff book (12.8). ADR 0003 puts
   anything persisted in a closed hierarchy, and `PersistedShapeTests` fails the build if a closed
   hierarchy (here `SessionStarted`) holds a union anywhere in its properties. A closed hierarchy is
   just as exhaustive: `Tariff.Prices` and `PriceCalculator.Lines` switch over it with no discard. The
   `TariffComponent` summary says so. The outline's 8.2 summary says "union TariffComponent(...)";
   the writer should call it a closed hierarchy and can use the ADR's decision table to explain why.
2. **The tariff types live in `Ohmline.Tariffs.Contracts`**, not `Tariffs.Domain` (8.2):
   `TariffId`, `TimeOfUseBand`, `TariffComponent` and its cases, `TariffSnapshot`. `StartSession` (in
   `Charging.Contracts`) and `SessionStarted` (in `Charging.Domain`) carry the snapshot, and a context
   may reach another only through its contracts (`ContextBoundaryTests`). `Tariff` (the validated,
   versioned definition) stays in `Tariffs.Domain`, as do the pricing types (8.3). **This needed one
   rule change:** a contracts project may now reference another context's contracts
   (`ContractsPurityTests`; `errata.md` and the editor are told). The context map already says Charging
   consumes `Ohmline.Tariffs.Contracts` (Customer/Supplier).
3. **The spend cap is checked against an upper bound, not the real price** (8.2). Charging cannot call
   `PriceCalculator` (it lives in `Tariffs.Domain`), and the exact price of a time-of-use session is
   only known at the end. `SessionTerms.CostOf` counts each kWh at the snapshot's highest energy rate
   plus the session fee, so the session stops before the hold runs out. Who runs the calculator when a
   session ends (canvas open question) is for Chapters 15 and 16; 8.3 only makes it possible ("whoever
   needs a price brings the data").
4. **The specification classes wrap the pattern predicates** (8.4) instead of repeating the logic. The
   outline asks for "both as classes and as static pattern-based predicates"; both exist, and writing
   the rule once is the production choice. The class form earns its keep where a rule must be a value:
   the router test combines two `IdleFeeApplies` with `And`/`Not`.
5. **Extra predicate `EndedWithoutEnergy`** (8.4): neither named rule needs a list pattern without
   being contrived (a list pattern cannot search for "some element", `CS8980` allows one slice), and
   the outline promises list patterns. This one is real: policy P7 of the settle-session board.
6. **Intents carry the session id** (8.5): `ReleaseSiteAllocation(SiteId, ConnectorId, SessionId)` and
   `UnlockToken(TokenUid, SessionId)`, not the outline's two-field examples. `SitePowerBudget` releases
   an allocation only for the session that holds it (7.8), and unlocking a token is safe only for the
   session that locked it. Two more intents: `StopCharging` (spend cap) and `WarnOfIdleFee` (idle fee).
   The intent cases are nested in the `ChargingIntent` union (7's convention for clashing names).
7. **`IdleFeePolicy` is configured by the tariff** (`IdleFeePolicy(IdleFee Fee)`), because the
   suspension event does not carry the grace period; `SessionPolicies.For(terms)` builds the set. The
   outline's third policy name was `SessionEndedReleasesAllocation` in the section summary and
   `ReleaseOnSessionEnded` in the code change; the code uses `ReleaseOnSessionEnded`, as do the canvas
   and the design-level board.
8. **`SuspendCharging` carries who suspended** (8.6): the outline lists state, events and Decide; the
   command had to say who, too. It gained a `SuspendedBy By` field (closed record `ByEv`/`ByCharger`)
   rather than splitting into two commands, following `PriorityClass` (7.8). Transitions between the
   two suspended states are allowed: the latest report says who.
9. **`SiteLocalTime` does not implement `IValueObject<,>`** (8.7): it is built from two values (an
   instant and a zone id) and wraps no single raw value. It has `TryCreate` returning
   `Result<SiteLocalTime, ValidationError>` like every other value object. It converts only from an
   instant to the wall clock; nothing in Chapter 8 needs the other direction, so no API for it was
   added. The section's DST tests use `FakeTimeProvider` as the outline asks (as a clock that crosses
   the change, and as the oracle for local time).
10. **8.3's calculator already handled DST correctly**, because it only ever converts instants to
    local time; 8.7 moved that conversion into the kernel's `SiteLocalTime` and added the tests that
    prove it. There was no DST bug to fix, and I did not plant one. If the writer wants the bug, it
    is the opposite direction (computing a band's start instant from "16:00 local"), which
    `SiteLocalTime`'s summary describes; a `wrong/` branch could show it, but none was requested.
11. **Tag annotations** use `8.N <title>` like earlier chapters; commit subjects `chNN-sMM: <title>`
    with the `Book-Section:` trailer. `Specifications.cs` holds three types (the outline names the
    file); everywhere else, one type per file.

## Surprises and gotchas (for the writer)

- **A conditional that targets a nullable union** (8.2): `return cond ? new Malformed(...) : null;` in
  a method returning `ValidationError?` fails with `error CS8604: Possible null reference argument for
  parameter 'value' in 'ValidationError.ValidationError(Malformed value)'`: the conditional is typed
  `Malformed?` first and then converted. Casting to `(ValidationError)` gives `CS0037: Cannot convert
  null to 'ValidationError' because it is a non-nullable value type`. The working form is
  `(ValidationError?)new Malformed(...)` (`Tariff.CountProblem`, `GraceProblem`). A plain `return new
  Missing(...)` converts without help.
- **A static-import field named like a type, again** (8.3): `TheDepotTariff.Energy` (an `EnergyRate`)
  and the `Energy` unit under `using static` gave `error CS0229: Ambiguity between 'TheDepotTariff.Energy'
  and 'Energy'`; renamed `BaseRate` in `ch08-s03` (touching the 8.2 test file). Same trap as
  `Known.Charger` in 7.4.
- **A method group that returns `ImmutableArray<T>`** does not convert to `Func<TIn, IEnumerable<T>>`:
  `history.SelectMany(policies.React)` gives `error CS0407: 'ImmutableArray<ChargingIntent>
  SessionPolicies.React(SessionEvent)' has the wrong return type` (a struct return would need
  boxing). Use a lambda.
- **`with` on a closed base works** for the stamp (`@event with { CommandId = ..., OccurredAt = ... }`)
  and for rounding price lines (`line with { Amount = ... }`); the leaf type is kept.
- **Nested property patterns over a closed hierarchy are exhaustive** (`SuspendCharging { By: ByEv }`
  plus `{ By: ByCharger }`), with no null arm needed for the non-nullable property.
- **`TimeOnly.IsBetween(start, end)`** already treats `end <= start` as a range past midnight, which is
  what `TimeOfUseBand.Contains` needs.
- **`TimeZoneInfo.TryFindSystemTimeZoneById`** finds IANA ids on Linux (ICU/tzdata). Windows .NET 6+
  also accepts IANA ids; untested here, hedge if mentioned.
- Money equality ignores decimal scale (`11.592m` rounded to `11.59m` equals `11.59m`), so expected
  lines can be written plainly.
