## Surprises and gotchas (for the writer)

1. **DbUp substitutes `$name$` variables**, and Akka.Persistence.Sql's DDL uses PostgreSQL's
   dollar quoting `$BLOCK$`: the first run failed with `System.InvalidOperationException: Variable
   BLOCK has no value defined` (from `DbUp.Engine.Preprocessors.VariableSubstitutionSqlParser`).
   `.WithVariablesDisabled()` fixes it; the comment in `Migrations.cs` says why.
2. **A public `Program` from top-level statements** clashes when a test project references two
   executables: `error CS0433: The type 'Program' exists in both 'Ohmline.Migrator, …' and
   'Ohmline.Node, …'` (also with Billing). The migrator therefore has an explicit
   `internal static class Program` with `Main`.
3. **DataAnnotations validation reads every public property.** A computed `SessionHistory`
   property on `ReadModelOptions` that threw for an invalid version turned the expected
   `OptionsValidationException` into a `System.Reflection.TargetInvocationException`; the
   mapping moved to `SessionHistorySource.Of(...)` in the endpoints.
4. **CS8509 caught the new integration event:** adding `SessionCompletedV2` to the closed
   hierarchy made `OutboxTables.WireNameOf` fail to build (`The switch expression does not handle
   all possible values of its input type … 'SessionCompletedV2' is not covered.`) until it got
   its arm. A nice demonstration of section 3.3's exhaustiveness on a real change.
5. **A nullable constructor parameter is still required** under
   `RespectRequiredConstructorParameters` (message in 20.2). Optional means "has a default".
6. **`snapshot-is-optional` is logged at INFO** by Akka.NET, and it is unsafe once events are
   deleted (the reference config says so). Turning it on is what made the `DeciderActor`
   whole-history check necessary; without it the state-sourced listing would have started empty
   from an unreadable snapshot.
7. **The published DDL differs from `autoInitialize`:** it has a `tags` column (unused in
   tag-table mode) and a different column order. Harmless, but `JournalInspectTests` had to change.
8. **Read adapters see deserialized objects, bound by type.** A traced event arrives as a
   `TraceEnvelope`, so an adapter bound to an event type would not see it; the legacy rows the
   chapter adapts are pre-tracing by design. Not tested: whether the SQL read journal's
   `EventsByTag` applies the adapters (projections never meet legacy rows in the sample).
9. **Renaming a type renames metric tag values.** `command.type` (section 18.1) is the command's
   type name, so `ReportConnectorFault` series stop and `ReportConnectorOutOfOrder` series start
   at the deploy. Not changed in code; worth a sentence in 20.7.
10. **Flaky under machine load (not a regression):** `Ohmline.Charging.Api.Tests.SessionEndpointsTests.
    Given_a_start_then_the_session_gets_the_tariffs_current_version` uses a 500 ms Ask timeout
    (`EdgeTestKit.Options`) and failed twice in full runs while another agent was running a
    tag verification on the same machine (load average 12–15); it passes alone and in quieter
    full runs. Four other timing tests failed once in the same loaded run and passed on rerun.
11. **The Aspire AppHost still connects the node as the PostgreSQL superuser.** The least-privilege
    role is proven by `LeastPrivilegeTests` and `MigrationTests`, not wired into the AppHost.

## Deviations from the outline (with reasons)

- **20.2:** `PhaseCount` was also added to `StartSession` (optional), so that the write path exists
  for a later release; the decider copies it into the event. `SessionTerms.PhaseCount` with
  `AssumedPhaseCount = 3` is the "default handling in Evolve". The frozen old shape went into
  `tests/golden/corpus/` already in 20.2 (rather than a file of its own), so 20.5 completes a
  corpus that 20.2 started.
- **20.3:** "measurand phase" is `string? Phase` (`L1`/`L2`/`L3`, null = total). The gateway sends
  no phase, so every reading written today has `Phase: null`; a phase reading never moves the
  session's meter (Evolve and both read models), and tests show it.
- **20.4:** the "demonstration legacy manifests" are the depot pilot's `charging.reservation-taken-over.v1`
  (split into two) and `charging.charge-point-heartbeat-recorded.v1` (`EventSequence.Empty`), read
  by `ChargingSerializer`. "Rows from before you owned the serializer" (Newtonsoft `$type` rows) is
  covered by the trade-off table, not by code: an adapter for them would need legacy CLR types with
  the old full names. The legacy types have manifests and golden files like any type (needed so
  that tests can seed a journal), though Charging never writes them.
- **20.6:** the outline's "connector reservations with expiry offsets" is implemented as v2 =
  `TakenAt` plus each reservation's `ExpiresIn` offset. "DeciderActor treats unknown snapshot
  versions as absent" is done where it can be correct: an unknown manifest makes the snapshot store
  fail the load (`UnknownManifestException`), `snapshot-is-optional` replays from the first event,
  and `DeciderActor` refills the cache. The actor cannot itself ignore a snapshot it was offered:
  the replay would then start after it. It adds the whole-history check instead.
- **20.7:** only C# names changed for the repair event, the commands, the refusal, the snapshot
  case and the status constant; only `ConnectorOutOfOrder` got a new manifest, as the outline asks.
  `ConnectorFaultCleared` became `ConnectorRepaired` (not "back in service", which collides with
  `MakeConnectorAvailable`'s summary). The client contracts' `RejectionCodes.ConnectorFaulted` and
  the phone's text were left alone: they are the driver app's published language (section 19.2),
  append-only, and the value is unchanged anyway. **Editor:** the style guide's §8.2 glossary row
  "Connector status … Faulted (renamed *Out of order* in 20.7)" can now name `OutOfOrder`,
  `ConnectorOutOfOrder` and `ConnectorRepaired`.
- **20.8:** the grants are two run-always scripts under `Grants/`, beside the five numbered ones.
  The SQLite development node keeps `autoInitialize` (the migrator is PostgreSQL-only). The node's
  least-privilege login is shown in tests, not in the AppHost. `IntegrationTests`' one-node-at-a-time
  collection stays: every node also binds pbm's fixed port 9110 (the fixture's comment says so).
- **20.9:** `session_history_v2` needed its own migration, `0006_session_history_v2.sql`. The
  read-model switch also changes `/sessions/{id}/events` (SSE) and `/tokens/{uid}/sessions`. The
  driver-app feed epoch (open since 14.8) is still not implemented.
- **20.10:** no other code; the PII test covers events in Domain and Contracts assemblies (snapshot
  DTOs in `*.Actors` are not referenced by `Ohmline.ArchitectureTests`).
