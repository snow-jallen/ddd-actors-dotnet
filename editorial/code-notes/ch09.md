Note for the prose: the **Given events are not stamped** (zero `CommandId`, `OccurredAt` of
0001-01-01). The charge point's Evolve never reads the stamp, so the history does not need one;
the session's Evolve reads `OccurredAt`, so `ChargingSessionTests` stamps its history with `.At(...)`.
**Expected events must be stamped** (`.At(Morning)` from `Stamps.cs`, 8.1): the stamp is part of
the fact. The harness cannot stamp generically, because the stamp lives on each context's event
base and there is no common interface (see deviation 2).

## Deviations from the outline (and why)

1. **`DeciderSpec` has `At(DateTimeOffset)` and `With(DecisionContext)` between Given and When**
   (9.2). The outline names `Given(events).When(command).Then(events)`. Every decision needs a
   moment (stamps, reservation expiry), and a hidden default time would make tests pass by
   accident, so the harness refuses `When` without one. Each test class wraps it once, e.g.
   `ChargePointSpec.Given(history).At(Morning)` in a private `Given(...)`.
2. **Expected events are stamped by the test** (`.At(Morning)`), not by the harness. The stamp
   (`CommandId`, `OccurredAt`, 8.1) lives on each context's event base record; there is no shared
   interface in the kernel, and adding one only for the harness would change the shared kernel's
   contract. The `Stamps.cs`/`TheDepot.At` extensions from 8.1 stay.
3. **`Ohmline.Testing` references CsCheck from `ch09-s04`.** The 9.2 code change says "references
   SharedKernel and Shouldly only", which holds at `ch09-s02` and `ch09-s03`. 9.4 asks for
   `DeciderProperties` in the same project, which needs CsCheck's `Gen<T>` (already in the
   allowed package set since `ch06-s08`). The csproj comment says what the project holds.
   `sample-architecture.md` §2.3/§3 do not list Ohmline.Testing's packages, so nothing there is
   contradicted.
4. **Ohmline.Testing references no xUnit.** It removes `xunit.v3` and the `Xunit` global using that
   `tests/Directory.Build.props` adds, and fails with Shouldly's `ShouldAssertException`, which
   every test framework reports as a failure.
5. **`DeciderSpec.Decision.Result`** (9.3) is an addition: the scenario tables describe the decision
   in words and compare strings, so they need the raw answer. `Then`/`ThenRejects` are unchanged.
6. **The Site Energy tests build their Given by deciding commands** (`Journal`), not by writing
   events by hand (9.2). An `AllocationsRebalanced` table written by hand would repeat the
   allocator's arithmetic in the test (the "expected value computed with the production formula"
   smell, in reverse). Every row's Then is still exact events.
7. **A domain change in 9.3 and one in 9.4.** 9.3: the reservation-renewal fix (errata). 9.4:
   `Configured.AllocationsFit`, the Assertions pattern as code, which the outline mentions only as
   a topic. Both are small and each is in its section's commit.
8. **Property test classes end in `Properties`** (`SitePowerBudgetProperties`), like 8.3's
   `PriceCalculatorProperties`; `docs/testing-strategy.md` now states it. (6.8's
   `MoneyPropertyTests` and `UnitPropertyTests` predate the rule and were not renamed, to keep
   Chapter 6's quotes valid.) The harness aliases are therefore named `...Checks`.
9. **9.5's TOU tests use the fake clock for the meter, not for a `DecisionContext`**: pricing is a
   domain service with no decider. The reservation and idle-fee tests do build `DecisionContext`
   from the fake clock as the outline asks.
10. **Tag annotations** use `9.N <title>` like earlier chapters; commit subjects
    `ch09-sMM: <title>` with the `Book-Section:` trailer.

## Surprises and gotchas (for the writer)

- **`FakeTimeProvider.SetUtcNow` cannot go back in time** (message above). Start a new clock.
- **Exit code 8** for a test program in which nothing ran; harmless at solution level unless the
  whole filter matches nothing (above).
- **CsCheck shrinks while it samples.** With the default 100 iterations a failing script shrank from
  ~40 commands to 15; with 1,000 to 5. CsCheck prints a seed (`-e CsCheck_Seed=...`) to replay a
  failure. CsCheck samples on all logical CPUs by default.
- **A union's `Equals` compares the case**, so `Equals(next, state)` in `EveryEventChangesTheState`
  works on `SessionState`/`ChargePointState`/`SitePowerBudgetState` directly (verified by the
  planted-bug run above).
- **Row order in a decision table with `when` guards is semantic.** The 9.3 fix swapped two rows;
  the compiler cannot help, because both rows match the same patterns. Only an example finds it.
- **A switch expression followed by `with`** (`name switch { ... } with { OccurredAt = Full }`) did not
  read well and was rewritten as a local variable plus `with`; not a compiler error, a style call.
- **`TheoryData<string, string, string>` enumerates `TheoryDataRow<...>`** with a `Data` tuple in
  xUnit v3 (`row.Data.Item1`), used by the two completeness guards in 9.6.
- **The known Chapter 2 race** (`Ch02.Hosted.Tests.ChargerAppTests.Given_a_running_host_when_it_stops_then_coordinated_shutdown_drains_first`)
  failed once in the working tree during 9.4 (719 of 720) and passed in four reruns straight
  after. The property tests use every CPU for a second or two, which may make the race likelier;
  nothing in `learn/` changed in this chapter.
