  public decimal Value

  constructor only.

merely fail to read an ambiguous case; it **refuses the whole union** on first use, for writing as
well, when one case can never be picked. `Available` has no properties, so even serializing an

'Ch03.LanguageLab.Tests.Available' can never be selected uniquely. The case type
'Ch03.LanguageLab.Tests.Occupied' recognizes every property name recognized by
'Ch03.LanguageLab.Tests.Available' and has no stricter required-property or unmapped-member
constraints.` That is why `StartBlocker` (two cases, one unique property each) exists.

## Deviations from the outline (and why)

1. **Union case records are in `ConnectorStatus.cs`, not in `UnionTests.cs`** (3.3). The outline
   says "case records in the test file"; I read that as "in the test project". Sample-architecture
   §5.1 requires a union and its cases in one file named after the union, and 3.9's actor and
   STJ tests reuse them.
2. **A second compile-error symbol, `DECLARATION_ERRORS`** (3.4). Roslyn reports no method-body
   diagnostics once a type declaration is in error, so CS9381/CS9382/CS9384 under plain
   `DEMO_COMPILE_ERRORS` hid every other demo error (verified). They sit in `#if
   DECLARATION_ERRORS` inside the file's `#if DEMO_COMPILE_ERRORS`, so they still exist "inside
   `#if DEMO_COMPILE_ERRORS`" as style-guide §6.3 asks, but need both symbols. The editor may want
   to mention this in the style guide.
3. **Extra learning types beyond the outline**: `ConnectorKey`, `TariffRates` (3.1),
   `InitializerGuardedKilowatts`, `ConnectorNumber` (3.2), `StatusReport` (3.3, the nested union
   needed for CS0029/CS8121), `ChargerNotification` (3.4, the abstract-record contrast), `StartError`
   (3.5, a union error type for the explicit hop), `StateOfCharge` (3.6, a value object to test
   `IValueObject` before Chapter 6's units exist), `GenericMath` (3.6), `KilowattHours`,
   `MeterSample` (3.7), `ChargingSnapshot`, `ReservationTimer` (3.8), and in 3.9
   `StructuralConnectorStatus`, `StartBlocker`, `ConfigurationValue`, `ConnectorEvent`,
   `TariffEvent`, `HandlerReportingActor`. Each exists to make one outlined claim testable.
4. **`IValueObject<TSelf, TValue>` also declares `TValue Value { get; }`** (3.6), as in the
   research notes. The outline names only `TryCreate` and `Create`; every value object wraps one
   raw value, and later serializer converters (ActorShell, §7) can use it generically.
5. **`ValidationError` placeholder is `sealed record ValidationError(string Message)`**, and
   `IValueObject.Create` throws `ArgumentException(err.Error.Message, ...)`. When 6.2 replaces it
   with `union ValidationError(OutOfRange, Malformed, Missing)`, that line must change (a union has
   no `Message`). Flag for the ch06 coder.
6. **`Map`, `Bind`, `Match` and `IsOk` are in an extension block inside the static `Result`
   class**, not a separate `ResultExtensions` class: one static class holds the factories and the
   extension members, and `Result.cs` stays the single file the outline names. The generic
   parameters of `Map`/`Bind`/`Match` are `TNext`/`TOut` (the union's own are `T` and `E`, exactly
   as in the outline).
7. **3.6's generic-math quantity is the LanguageLab `Kilowatts`**, which gains the operator
   interfaces (a visible diff), rather than a new type.
8. **The extension receiver in 3.7 is `decimal value`**, not `decimal v` as in the outline text,
   following the "no abbreviations" spirit of the sample.
9. **3.9's STJ classifier tests use two unions**: the classifier cannot be demonstrated working on
   `ConnectorStatus` at all (see the surprise), so `StartBlocker` shows where it works and
   `StructuralConnectorStatus` where it refuses.
10. **Line-length fix-forward** inside this chapter: `ConnectorKey.cs` (3.1's line fixed in 3.2)
    and `MeterSample.cs` (3.7's line fixed in 3.8). Both are doc comments. Tagged commits were not
    amended. No code from earlier chapters needed a fix; `editorial/errata.md` was not touched.
11. **Tag annotations** follow this brief and Chapter 2 (`"3.1 Learning tests: pinning down a
    language"`); commit subjects match `outline.json` exactly, with the `Book-Section:` trailer.
