## Surprises and gotchas (for the writer)

1. **SBR has no `StableAfter` in Akka.Cluster.Hosting 1.5.73.** `KeepMajorityOption` has only
   `Role` (and `ConfigPath`); `stable-after` is set with `AddHocon(...)`. Verified by reflection.
2. **`HashCodeMessageExtractor.ShardId(object)` is obsolete:** `error CS0618:
   'HashCodeMessageExtractor.ShardId(object)' is obsolete: 'Use ShardId(string, object?) instead.
   Since v1.5.15'`. The tests call `ShardId(entityId, messageHint: null)`.
3. **The shard of an id is stable:** `OHM-SLC-0042` is shard 67 in every process (Akka's own
   murmur hash, not `string.GetHashCode`), so it can be pinned in a test.
4. **A region on a node without its role hosts nothing.** `SqliteNode` must give its cluster the
   `charging` role, or the regions only proxy.
5. **`Passivate` sent to a non-shard parent** (a plain test actor's guardian) is a dead letter with
   a WARNING; harmless. Tests that check passivation make a `TestProbe` the parent with
   `ChildActorOf(props, cancellationToken: Ct)` (xUnit1051 demands the token).
6. **`Context.Stop(Self)` in a persist callback** loses the reply to the command being persisted,
   not only the commands behind it (wrong branch above).
7. **`Ok<T>` clashes**: `Microsoft.AspNetCore.Http.HttpResults.Ok<TValue>` and
   `Ohmline.SharedKernel.Ok<T>` in one file give `error CS0104: 'Ok<>' is an ambiguous reference`.
   The Api projects therefore read results with a small `TryGet` extension and do not import
   `Ohmline.SharedKernel` in endpoint files.
8. **A variable in an `or` pattern** is still an error in C# 15: `error CS8780: A variable may not
   be declared within a 'not' or 'or' pattern.` `IdTokenState` got `Driver` and `ActiveSession`
   members instead, used in `when` clauses.
9. **Union structs have no `==`**: `error CS0019: Operator '==' cannot be applied to operands of
   type 'TariffEntry' and 'TariffEntry'`; compare `.Value` with `Equals`.
10. **`DeciderSpec.ThenRejects<ValidationError>()` fails** for an error union that has
    `ValidationError` as a case: the spec unwraps to the innermost case. Use
    `ThenRejects<Malformed>()` (the tariff book test does).
11. **`ShardOptions`/`ClusterSingletonOptions` are mutable classes**, hence
    `EntityShardOptions.Create()` returns a new one each time.
12. **NU1009 with Aspire:** pinning `Aspire.Hosting.AppHost` in CPM, as the architecture asked,
    fails: `error NU1009: The following PackageReference items are implicitly defined and cannot
    define a PackageVersion item: Aspire.Hosting.AppHost.` The SDK brings it at 13.6.4.
13. **ASPIRE010** (`Ohmline.AppHost is configured with AspireUseCliBundle=false...`) breaks
    `-warnaserror`; `<AspireUseCliBundle>true</AspireUseCliBundle>` silences it, and then
    `dotnet run --project src/Ohmline.AppHost` runs through the Aspire CLI bundle (it printed
    "Created settings file at 'aspire.config.json'" and the dashboard URL). The installed CLI is
    13.6.3 and said "A new version of Aspire is available: 13.6.4".
14. **Three nodes at once on an empty PostgreSQL** fail `autoInitialize`: `Npgsql.PostgresException
    (0x80004005): 23505: duplicate key value violates unique constraint "pg_class_relname_nsp_index"`
    → `System.ApplicationException: Failed to initialize SQL Journal.` (and the same for the
    snapshot store, `pg_type_typname_nsp_index`). The AppHost makes `node-2`/`node-3` wait for
    `node`'s `/health`; the integration tests run one node at a time (a shared collection). Chapter
    20's migrator removes the cause.
15. **`CollectionBehavior(DisableTestParallelization = true)` is an error in xUnit v3 4.0.2:**
    `error CS0619: 'CollectionBehaviorAttribute.DisableTestParallelization' is obsolete: 'Please set
    ParallelizationAttribute.Mode instead...'`. A named collection shared by the classes is the
    simple alternative used here.
16. **Npgsql must be referenced by the node**; Akka.Persistence.Sql does not bring the PostgreSQL
    driver.
17. **Minimal API inference:** `ITariffCatalog` is marked `[FromServices]` in `StartAsync` so that
    a host without an implementation fails at the request, not at startup (until 12.8 only
    Development registered one).

## Deviations from the outline (with reasons)

- **12.1:** the cluster setup is a Node extension (`WithOhmlineCluster`) instead of inline in
  `Program.cs`, so `Ohmline.Node.Tests` (12.9) can run the same code. `ClusterRoles` lives in
  ActorShell because `EntityShardOptions` (12.2) needs the role too.
- **12.2:** region keys live in each context's Contracts (the Api projects reference Contracts
  and not Actors); the per-context extractors are static classes (`ChargingMessageExtractors`, ...)
  so that 16.7's proxies can reuse them. `ChargePointDirectory` is deleted (planned in ch11 notes).
- **12.3:** the static `Props(id, clock)` factories stay, for tests that start an actor
  themselves; regions use `resolver.Props<T>(typedId)` (a typed id, not the raw string).
- **12.4:** added `DeciderActor.Passivate()` and session self-passivation on `SessionEnded`, so
  that "Passivate with a custom stop message instead of Context.Stop(Self)" has a call site and the
  wrong branch a precise one-line diff. Idle passivation itself is the shard's (2 minutes).
- **12.5:** request DTOs map to commands in the handlers; 422 for invalid fields, 409 for
  rejections, 404 for unknown route ids or empty aggregates. `POST /sessions` takes a client-chosen
  version 7 session id (so a retry names the same session) and a tariff **id**; the snapshot comes
  from an `ITariffCatalog` port, a Development stand-in until 12.8. Site Energy's `GET
  /sites/{id}/budget` needed a new query and view in Site Energy's contracts (two manifests). Site
  Energy and Driver Accounts have their own `AskTimeout` keys (`Ohmline:SiteEnergy:AskTimeout`,
  `Ohmline:DriverAccounts:AskTimeout`), not in the architecture's key table. The dev scaffolding
  endpoints are plug-in, unplug, fault, repaired (charger-originated events); the outline did not
  list them.
- **12.6:** only accepted commands that stored events are remembered (what the journal can
  rebuild); the window stores versions, not reply objects; snapshots carry it as an optional
  field under the same `.v1` manifests; same key with a different body is not detected (Chapter
  19's 400). The test fixtures' shared command id had to go (errata).
- **12.7:** `DriverRef` (an opaque account reference) is in Driver Accounts' contracts;
  `GET /tokens/{uid}` and `GetIdToken`/`IdTokenView` were added so that `Location` points somewhere;
  DeciderActor gained command-aware reply hooks for `TokenLocked`/`TokenLockRefused`; the extra
  reply family members are `TokenCommandAccepted`/`TokenCommandRejected`.
- **12.8:** `TariffBookState` is a record holding a dictionary of `union TariffEntry`; the
  singleton uses `createProxyToo: false` plus `WithSingletonProxy<TariffBookProxy>` (the outline's
  pair), with `TariffBookProxy` as the registry key in the contracts. The tariff endpoints are in
  Charging.Api (`TariffEndpoints`). Rounding is always cents through the API.
- **12.9:** `AddTariffsContext` is wired too, and the base uses the node's own
  `WithOhmlineCluster` with an in-memory configuration instead of a hand-written self-join.
- **12.10:** **three named resources (`node`, `node-2`, `node-3`), not `WithReplicas(3)`**, and a
  static seed on `node` (ADR 0010: replicas get remoting ports only at run time; Akka.Aspire needs
  Redis or Azure Table discovery, which are not approved packages). `Npgsql` 10.0.3 is used from
  12.10, not 13.4 (the node needs the driver). `Aspire.Hosting.AppHost` is not pinned (NU1009).
  Health endpoints come from ServiceDefaults and replace the node's hand-made `/alive`.
- **12.11:** integration test classes share one xUnit collection so that nodes do not race to
  create tables.
