**Sequence diagram facts:** *Persist failure:* sender → actor: command → Decide → `PersistAll` →
journal fails the `AtomicWrite` → `OnPersistFailure` (ERROR) → actor stops → the commands in the

`OnPersistRejected` once per event of the batch → the first call replies `persistence-rejected` →
no event handler runs (state unchanged) → Akka.NET **still runs the `onComplete` callback**, which
finds `_writeFor` null and tells no one → stashed commands continue normally.

## Surprises and gotchas (for the writer)

1. **A rejected `PersistAll` still runs its `onComplete`.** Before 11.6, a journal rejection made
   the shell reply `CommandAccepted { Version = 4 }` although nothing was stored (observed with a
   two-event decision). Akka.NET calls `OnPersistRejected` once per event and then the completion
   callback. Hence `_writeFor`/`AnswerWrite`.
2. **Rejected events use up their sequence numbers.** After a rejection of event 2, `LastSequenceNr`
   is 2 although the journal holds only 1; the next accepted command is version 3. Versions are
   monotonic, not contiguous (ADR 0008 says so).
3. **`serialize-messages = on` swallowed journal failures and rejections.** Akka.Persistence's
   internal `AsyncWriteJournal+Desequenced` carries the exception, and Akka's Newtonsoft copy fails:
   `[ERROR] Swallowing exception during message send` / `SerializationException: Failed to serialize
   and deserialize payload object [Akka.Persistence.Journal.AsyncWriteJournal+Desequenced]. ...
   Actor type: [Akka.Persistence.Journal.AsyncWriteJournal+Resequencer]` → `InvalidCastException:
   Unable to cast object of type 'Newtonsoft.Json.Linq.JObject' to type
   'Newtonsoft.Json.Linq.JValue'`. The actor then waits in its stash forever (the test timed out
   after 6 s). `LocalExceptionJsonConverter` lets the copy keep the original exception by reference;
   the same applies to `SaveSnapshotFailure`. The research spike never saw this because it ran
   without `serialize-messages`.
4. **On SQLite, a poison event fails its whole replay batch.** The log says "after sequence number
   0" although event 1 is fine: Akka.Persistence.Sql deserializes up to `replay-batch-size` rows
   before the actor sees any. The runbook says the number is a lower bound.
5. **`DeleteMessages` keeps the last row** (`deleted = True`, payload still there); there is no
   `journal_metadata` table on SQLite with `autoInitialize`. "Deleted" is not "erased".
6. **Timers and fake clocks:** the timer delay is computed from the `TimeProvider`, but Akka's
   scheduler runs on its own clock. Tests use `akka.scheduler.implementation =
   "Akka.TestKit.TestScheduler, Akka.TestKit"` (`ActorTestConfig.VirtualTime`) and advance both. On
   the `TestScheduler` even a zero delay waits for `Advance(TimeSpan.Zero)`, and advancing before
   recovery has armed the timer does nothing (the first draft of the lapsed-reservation test failed
   with `AwaitAssert failed, timeout [00:00:03] is over after [31] attempts`).
7. **A recovered timer can make a test racy:** see Errata (`TwoIncarnationsTests`).
8. **`Backoff.OnStop(props, name, min, max, randomFactor)` is obsolete** in 1.5.73: `error CS0618:
   'Backoff.OnStop(Props, string, TimeSpan, TimeSpan, double)' is obsolete: 'Use the overloaded one
   which accepts maxNrOfRetries instead.'` The sample passes `maxNrOfRetries: -1`.
9. **A nullable union is `Nullable<T>`:** `_ => null` in a switch returning `ListingError?` gave
   `error CS0037: Cannot convert null to 'ListingError' because it is a non-nullable value type`
   (the switch's natural type was the union); `default(ListingError?)` fixes it.
10. **`ToListAsync` is ambiguous** in the Charging actor tests: `error CS0121: The call is ambiguous
    between ... System.Linq.Async ... and ... System.Linq.AsyncEnumerable` (.NET 11 ships its own;
    Akka.Persistence.Sql brings the old package). Also `SelectMany` over a collection expression
    resolved to LanguageExt's `ArrExtensions.SelectMany` (CS0411; LanguageExt.Core comes with
    Akka.Persistence.Sql). The sample avoids both.
11. **`EventFilter.ExpectOneAsync(Action, ...)` is obsolete** (`CS0618 ... Use
    ExpectOneAsync(Func<Task>, CancellationToken) instead beginning in Akka.NET v1.5`).
12. **Passing test output is not printed by `dotnet test` (MTP).** To see `ITestOutputHelper` lines,
    run the test assembly directly: `dotnet tests/Ohmline.Charging.Actors.Tests/bin/Debug/net11.0/
    Ohmline.Charging.Actors.Tests.dll -method "*Given_200_events*" -showLiveOutput`.

## Deviations from the outline (with reasons)

- **11.1 "whether a snapshot was used":** at `ch11-s01` there is no `SnapshotOffer` handler yet
  (the outline puts it in 11.2), so the INFO line gains "snapshot at N" / "no snapshot" in
  `ch11-s02`. The `git diff ch11-s01 ch11-s02 -- src/Ohmline.ActorShell/Deciders/DeciderActor.cs`
  shows it arriving.
- **11.1 RecoveryTests location:** `tests/Ohmline.Charging.Actors.Tests/RecoveryTests.cs` (project
  root, as the outline's path suggests). The "Decider.Fold over the same events" is
  `ChargePoint.Fold(events)` (which calls `Decider.Fold`) over the events read back from the
  journal, compared through the status reply (which shows every field of the state).
- **11.2 snapshot hook:** "through the OnEventApplied hook" is implemented in the same place (the
  private `Apply`, right before `OnEventApplied`), not inside the overridable hook, so a subclass
  that overrides `OnEventApplied` for timers (11.4) cannot switch snapshots off by forgetting
  `base`. The cadence is the overridable `SnapshotEvery`. Snapshot DTO/manifest hooks are
  `ToSnapshot`/`FromSnapshot` (abstract); a null snapshot means "nothing worth keeping" (the initial
  states).
- **11.2 JournalTourTests:** the snapshot row test writes 200 events so that it also shows the
  older snapshot (at 100) deleted.
- **11.3:** `UnknownManifestException` (ActorShell) was added so that the log can name the manifest;
  its message is unchanged, so `ManifestJsonSerializerTests` and `SerializationTests` still pass.
  `SqliteNode.TellAsync` was added for the poison test.
- **11.4:** "tests with a FakeTimeProvider-built DecisionContext and short TestKit intervals" uses
  Akka's `TestScheduler` (virtual time) instead of short real intervals: the reservation hold is a
  fixed 15 minutes in the decider, and virtual time keeps the tests deterministic. To let a timer
  decide a command, `DeciderActor.Handle` became `protected void Handle(TCommand, IActorRef
  replyTo)`.
- **11.6 "wrap the entity actors in BackoffSupervisor in Node":** the only place the node creates
  entity actors is `ChargePointDirectory` (registered by `AddChargingContext()`), so the wrapping is
  there. Sessions, budgets and listings have no directory before Chapter 12. 11.6 also added
  `PersistenceFailureTests` (tests in the same commit as the code); 11.8 rewrote them on the spec,
  which is what the outline asks for in 11.8.
- **11.7:** the listing's command, query and view have manifests and golden files too (they cross
  the wire), not only the event and the snapshot. `ListingError` has two cases (blank display name,
  text too long). The listing actor is not wired into the node.
- **11.8:** `PersistenceShellSpec` is an abstract base class (a test class derives from it, as from
  `PersistenceTestKit`) rather than a static helper; the outline's "Then(reply, persisted events)"
  is `ThenAsync(reply, params persisted)`. `RecoveryTests`, `RecoveryFailureTests`,
  `ReservationExpiryTests` and the listing tests stay on `PersistenceTestKit`, because they drive
  recovery, virtual time or several incarnations step by step.
