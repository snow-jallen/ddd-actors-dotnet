**Files:**

## Surprises and gotchas (for the writer)

1. Replays must not count: domain counters live in `OnEventApplied`/`Apply`, never in recovery
   handlers (s01, s09 tests).
2. `MeterListener` callbacks are per measurement type: a `long` and `double` recorder misses `int`
   gauges silently (found in s02; the shard gauges are `long`).
3. `ClusterShardingStats.Regions` is empty until a region has a shard allocated (s02 debugging).
4. `EventStream.Subscribe<T>` does not take an interface type parameter here (CS0308 for
   `IActorTelemetryEvent`); use `Subscribe(Self, typeof(IActorTelemetryEvent))` (s02).
5. `ActorRefs.Nobody` swallows messages without a dead letter (s03).
6. `MetricCollector.WaitForMeasurementsAsync(n, CancellationToken)` can hang; `MatchesTags(new(...))`
   is ambiguous (s03).
7. Akka's MEL category is always `Akka.Actor.ActorSystem` (s04 test).
8. `DisableTracing` does not stop the OpenTelemetry SDK; the factory's sources die with their
   container; no host registers the factory unasked (s06).
9. Prometheus keeps `kWh` as `_kWh` and maps `1` to `_ratio` (s07).
10. Petabridge.Cmd defaults to `0.0.0.0:9110`; a port clash kills only the cmd actor (s08).
11. An SLO ratio needs `or vector(0)` on its good-events side (s09).

## Deviations from the outline (with reasons)

1. **s01: `DeciderActor` "records via hooks"** is one new hook, `OnDecided`, plus the existing
   `OnEventApplied`/`OnRecovered`; each context's actor overrides them and calls its metrics class.
   The shell cannot know Charging's instrument names. `ChargePointListingActor` is counted too.
2. **s01: the site utilization gauge reports the fullest site on the node** (one value, no tag),
   not one value per site: a per-site series would carry an entity id, which this section forbids.
   The remarks name the trade-offs (passivation keeps the figure; a stale figure after rebalance).
3. **s01: `SessionsStarted` and `EnergyDelivered` carry no tags.**
4. **s02: the shell's metrics are an Akka.NET extension** (`ActorShellMetrics.For(system)`) that
   finds the host's `IMeterFactory` through Akka.Hosting's container, instead of a constructor
   parameter on `DeciderActor`: otherwise every decider of every context, and their tests, would
   change constructors. Lifecycle counters (named in the summary, not the code change) were added
   as `LifecycleMetricsListener`. **Mailbox depth has no code**: reading it needs a cast to the
   internal `ActorCell` per actor (research §6.1); treat it in prose as the caveat the outline asks for.
5. **s02: shard stats come from `GetClusterShardingStats`**, as the outline says, so every node
   reports cluster-wide totals; the dashboard and docs use `max`, not `sum`.
6. **s03: the s01/s02 tests keep `InstrumentRecorder`** (the hand-made `MeterListener`); 18.3 adds
   `MetricCollector<T>` tests beside them rather than rewriting them, so the diff is about 18.3.
   The writer can show both: the mechanism (18.1) and the supported tool (18.3).
7. **s04: `ChargingJourneyActor` and `ChargerConnectionActor` now log through `ILogger<T>`**
   (source-generated); `[LoggerMessage]` needs `ILogger`, not Akka's `ILoggingAdapter`. The shell's
   own logs stay on Akka's adapter, correlated by `AddAkkaTraceCorrelation`. The correlation is
   registered in the hosts' `Program.cs`, ahead of `AddServiceDefaults()`, because ServiceDefaults
   (also used by Billing) knows no Akka.NET. The s04 commit also carries a test-only fix forward
   (SQLite Ask timeouts; errata).
8. **s05: `/alive` and `/health` were replaced** by `/health/live` and `/health/ready`; the
   AppHost probes `/health/ready`. ADR 0010 and the README's ch10-s01 row still mention the old
   paths historically (they describe earlier tags).
9. **s06: `ChargingDiagnostics` was not switched to `ActivitySourceFactory`.** It is compatible
   for export (verified), but (a) the factory's rules, the reason to adopt, do not reach the
   OpenTelemetry SDK; (b) a factory source dies with its container, while Charging's one span site
   (the projection runner inside an Akka.NET stream) would need the source threaded from the
   ReadModels extension through the daemon and runner; (c) the API is RC. ADR 0013 records this and
   the adoption criteria; `AddTracingTests` is the "test" of the outline.
10. **s07: one LGTM container** stands for Prometheus 3, Tempo, Loki and Grafana; Prometheus 3's
    OTLP receiver is used directly by the Collector (`otlphttp` to `/api/v1/otlp`). A Grafana
    provisioning file `grafana-dashboards.yaml` was needed beyond the three files named.
11. **s08: the port is configurable** (`PetabridgeCmd:Port`) because the AppHost runs three nodes
    and a gateway on one machine; the host is fixed at `127.0.0.1`. A runbook was added.
12. **s09: the SLI counts abandonments too** (tag `outcome`), and journeys ended by the driver's
    token or card are excluded from the SLO; Prometheus needs its own config file mounted to load
    rules (`rule_files`), so `prometheus.yaml` (the image's, plus one stanza) was added.
13. **Tag message of `ch18-s01`** reads `ch18-s01: Domain metrics with a cardinality budget`
    instead of the `18.1 …` form the other tags use; per the no-moving-tags rule it was left as it is.
