## Surprises and gotchas (for the writer)

1. **Schema creation deadlocked a running projection** (s02): `40P01: deadlock detected` in
   `NpgsqlOffsetStore.SaveAsync`, 1 run in 3, once there were seven streams. `ALTER TABLE ... ADD
   COLUMN IF NOT EXISTS` takes an ACCESS EXCLUSIVE lock even when the column exists. Fixed with a `DO`
   block that checks `information_schema.columns` first.
2. **`jsonb` reorders keys**, so a polymorphic payload read back from the outbox has `type` somewhere
   in the middle; `AllowOutOfOrderMetadataProperties = true` (.NET 9+) lets System.Text.Json find it.
   Without it, deserializing a stored event fails.
3. **Two resilience handlers.** `AddServiceDefaults` puts `AddStandardResilienceHandler()` on every
   `HttpClient`; adding another for TallyPay would nest two retry loops (up to 16 calls).
   `RemoveAllResilienceHandlers()` is the way out, but in Microsoft.Extensions.Http.Resilience 10.11.0
   it is experimental: `error EXTEXP0001: '...RemoveAllResilienceHandlers(IHttpClientBuilder)' is for
   evaluation purposes only and is subject to change or removal in future updates. Suppress this
   diagnostic to proceed.` Suppressed with `#pragma` and a comment naming 16.4.
   `TallyPayClientTests` proves one loop: 4 requests, not 16.
4. **`InlineData` with decimals** goes through `double`: `3.085` arrived as
   `3.0849999999999999644728632120` and rounded to 308. Decimal tables use `TheoryData<decimal, ...>`.
5. **DistributedPubSub is eventually consistent.** The first AppHost run of the simulator timed out
   waiting for `RemoteStartTransaction`: the node logged `Message [RemoteStart] wrapped in
   [$DeadLetterWithNoSubscribers] from [akka://ohmline/system/distributedPubSubMediator...]`, 0.26 s
   after the gateway logged that the charger had booted and subscribed. The registry reaches other
   nodes by gossip (about a second). Hence the port's 7 × 5 s attempts and the gateway's in-flight
   deduplication (a repeated ask joins the pending call; the charger is asked once).
6. **The mediator's role.** `WithDistributedPubSub(ClusterRoles.Charging)` (Chapter 14) runs the
   mediator only among charging nodes; the gateway's subscription would never be seen. The mediator now
   runs on every role (`role: ""`).
7. **`Publish` keeps the sender.** A `Publish` sent with `Ask` reaches the subscriber with the asker as
   `Sender`, so the subscriber's reply completes the ask (verified by
   `GatewayChargerCommandPortTests` on a real mediator).
8. **`Malformed` is ambiguous** in the gateway: the shared kernel's `ValidationError` case
   `Ohmline.SharedKernel.Malformed` and `Translation.Malformed` (CS0104); an alias `using Malformed =
   Ohmline.DeviceGateway.Ocpp.Translation.Malformed;`.
9. **`Charging` is a namespace** (again, as in Chapter 15): a test fixture property named `Charging`
   failed with CS0118; it is `MidSession`.
10. **A union struct and Shouldly** (again): `OcppFrameParser.Parse(text).ShouldBeOfType<Err<...>>()`
    fails; `.Value.ShouldBeOfType<...>()` works.
11. **Raw strings that start with a quote** (`""""meterStart"...`) do not compile (CS8997); test frames
    are built from anonymous objects with `JsonSerializer.SerializeToElement` instead.
12. **`dotnet sln add` with a referenced project** of the same file name in the folder fails with
    "Solution folder 'tests' already contains a project with the filename 'Ohmline.Testing.csproj'" and
    adds nothing; those entries were added to `Ohmline.slnx` by hand.
13. **`pkill -f Ohmline.AppHost` killed the shell that ran it** (its own command line matched). Run it
    on its own. DCP cleans up its processes and the PostgreSQL container about 20 s after the AppHost
    stops.

## Deviations from the outline (with reasons)

1. **`Microsoft.Extensions.Http.Resilience` was already in CPM** (since `ch12-s10`, for
   ServiceDefaults). s04 adds the package reference to Billing and the TallyPay handler, not the
   `PackageVersion`.
2. **Integration-event fields are plain values** (`Guid SessionId`, `string TokenUid`, `string
   ConnectorId`), as `src/Charging/Ohmline.Charging.Contracts/README.md` (Chapter 5) prescribes for
   the Published Language; the outline names them by their kernel types. Each event also has `EventId`
   (derived, idempotency) and `OccurredAt`.
3. **The relay keeps a small working table** (`read_models.integration_relay_sessions`) because
   `SessionEnded` names neither the start time nor the tariff. It stores the rates the session was
   priced by, not the tariff.
4. **The price is `SessionTerms.CostOf`'s rule** (every kWh at the highest energy rate plus session
   fees), not the Tariffs price calculator, which Charging's read side may not reference. It is exactly
   what the journey captures, so receipt and capture agree. It is not rounded: a 7.35 kWh session at
   USD 0.42 shows `3.087`. TallyPay is asked for whole cents (`ToMinorUnits`, 309). Rounding receipts
   with the tariff's `RoundingPolicy` belongs with the journey's capture and was left alone.
5. **The feed contract (`ChargingFeedPage`) is in `Charging.Contracts/Integration`**, beside the events,
   with each event as raw JSON; the outline says only "paged JSON feed".
6. **Billing reads the feed from its stored position**, not by following `next`; the two are the same
   page.
7. **Billing names holds by the caller's id** (`PlaceHoldRequest.HoldId` = the journey's key), so a
   void needs only the key (Chapter 15's `VoidHold(IdempotencyKey)`) and a repeated request names the
   same hold. A declined preauthorization is not stored; asking again goes to TallyPay under the same
   key, which answers the same.
8. **Billing in s03 holds without a provider**; s04 puts TallyPay behind the same endpoints.
9. **`OcppTranslator.Translate` takes a `Call`**, not any frame: results and errors are answers to the
   gateway's own calls, which the connection actor matches by message id.
10. **The gateway chooses the session's tariff and spend cap** (`Ohmline:Gateway:TariffId` and
    `SpendCap`, defaults `slc-standard` and 50, matching the journey's hold) and learns the site from the
    charge point region, at boot and on every heartbeat. `StartSession` needs both and the journey's
    `RemoteStart` carries neither. A real operator would configure both per site.
11. **A DistributedPubSub topic per charge point**, not a `charger-commands` region (the outline's
    either/or): a sharded entity would sit on any gateway node, not on the one holding the socket.
12. **`WithOhmlineCluster` moved to `Ohmline.ActorShell/Clustering`** with a role parameter, so the
    gateway joins exactly as the node does.
13. **The charging-journey proxy is registered on the gateway but not yet used**; the outline lists it.
14. **No WebSocket-level test of the gateway host**: a gateway alone has no charging role, so its proxies
    would find no region; the system test covers the socket end to end.
15. **The poller maps Northgate's VEN ids through configuration** (`Sites`), and is a cluster singleton
    (`grid-signal-poller`); the outline does not say where it runs.
16. **The dispatcher is not a full "at least once to a disconnected charger"**: a charger that is not
    connected gets no profile; the event is retried, recorded in `projection_failures`, and skipped.
    The next allocation corrects it. Stated in `docs/acl/northgate.md`.
17. **`InMemoryPaymentPort` and `LoggingChargerCommandPort` are kept** (no longer registered by the
    node) for the integration and node tests, which run a journey without Billing or a gateway.
18. **Extra docs:** `docs/acl/tallypay.md`, `docs/acl/ocpp-subset.md`, `docs/acl/northgate.md` and a
    Billing section in `docs/persistence-choices.md`.
