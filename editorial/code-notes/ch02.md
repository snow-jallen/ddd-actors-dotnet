**Tests** (`learn/Ch02.ActorsByHand.Tests/DoubleBookingTests.cs`)

- `Given_a_free_racy_connector_when_two_drivers_tap_at_once_then_both_start`: asserts

- `Given_a_free_locked_connector_when_two_drivers_tap_at_once_then_one_starts`.
- **How the determinism works** (worth a paragraph): `authorize` is `WaitForOtherDriver`, which
  calls `Barrier.SignalAndWait(MeetingTimeout)` (1 s) on a `Barrier(participantCount: 2)`. With the
  racy connector both threads pass the check, meet in the barrier, and both assign. With the lock
  only one thread can be inside, so the barrier times out after 1 s, that driver continues, and the
  second sees the connector occupied (it never calls `authorize`). `TwoDriversTapAtOnce` runs the
  two calls with `Task.Run` and `Task.WhenAll`. Ran 15 times in a row: always the same result.

## ch02-s02: A mailbox in sixty lines

**Types to quote**

- `learn/Ch02.ActorsByHand/Mailbox.cs` (49 lines, the "sixty lines" with room to spare):
  - `Channel.CreateUnbounded<TMessage>(new UnboundedChannelOptions { SingleReader = true })`;
  - the constructor starts `_loop = Task.Run(ProcessMessagesAsync)`;
  - `Tell(TMessage)` is `_channel.Writer.TryWrite(message)`: returns at once, and a stopped mailbox
    drops the message (the doc comment says so; it is the by-hand dead letters);
  - `ProcessMessagesAsync`: `await foreach (var message in _channel.Reader.ReadAllAsync())
    _handle(message);` inside a `try`; on an exception it completes the writer with that exception
    and rethrows, so `Completion` faults and later tells are dropped;
  - `Completion` (the loop task); `DisposeAsync` completes the writer, so the queued messages are
    still processed, then awaits the loop with `ConfigureAwaitOptions.SuppressThrowing`.
  - The handler is a synchronous `Action<TMessage>`, like Akka's `Receive`; there is no async
    handler by hand (2.8 discusses `ReceiveAsync`).
- `ConnectorMessage.cs`: `public abstract record ConnectorMessage;` with `sealed record`
  `StartSession(string SessionId, string TokenUid)` and `EndSession(string SessionId)`. A plain
  abstract record on purpose: closed hierarchies arrive in 3.4, so `Handle` needs a `default` arm.
- `ConnectorEvent.cs`: `SessionStarted(ConnectorId, SessionId)`,
  `SessionRejected(ConnectorId, SessionId, RejectionReason Reason)`,
  `SessionEnded(ConnectorId, SessionId)`; `RejectionReason.cs`: `ConnectorOccupied`,
  `TokenNotAuthorized`.
- `ConnectorActor.cs` (74 lines at this tag): constructor `(connectorId, Func<string, bool>
  authorize, Action<ConnectorEvent> publish)` creates `new Mailbox<ConnectorMessage>(Handle)`;
  `Tell` forwards to the mailbox; `Handle` is a `switch` statement (`default: throw new
  ArgumentOutOfRangeException(...)`); `Start` is the same check, token check, assign as
  `RacyConnector`, without a lock, publishing an event for every outcome; `End` ignores an
  `EndSession` for a session that is not active ("a repeated EndSession is harmless").
  - Why an explicit constructor instead of a primary constructor: the field initializer
    `new Mailbox<ConnectorMessage>(Handle)` would reference an instance method, which C# does not
    allow (CS0236). Same in `Mailbox` (`Task.Run(ProcessMessagesAsync)`).

**Tests** (`ConnectorActorTests.cs`)

- `Given_a_free_connector_when_two_drivers_tap_at_once_then_one_session_starts`: **the same
  barrier harness as 2.1**. Only the first message reaches the token check; the second waits in the
  mailbox, so the barrier times out after 1 s and exactly one `SessionStarted` and one
  `SessionRejected` (`ConnectorOccupied`) are published.
- `Given_a_free_connector_when_fifty_drivers_tap_at_once_then_one_starts`: `Parallel.For` over 50
  tells; one `SessionStarted`, 49 `SessionRejected`.
- `Given_an_occupied_connector_when_the_session_ends_then_a_new_one_starts`: the published list is
  exactly `[SessionStarted a, SessionEnded a, SessionStarted b]` (the second `EndSession("a")` is a
  no-op).
- `Given_a_free_connector_when_the_token_is_not_authorized_then_it_is_rejected`.
- The events go into a plain `List<ConnectorEvent>`, with the comment "Only the mailbox loop adds
  to _events; each test reads it after the loop has finished." Each test disposes the actor
  (`await using (...) { ... }`) before asserting, and disposal drains the mailbox. A good aside:
  even the test's list follows the single-writer rule.

## ch02-s03: Tell, don't ask: reply addresses and futures

**Types to quote**

- `ReplyTo.cs`: `public delegate void ReplyTo<in TReply>(TReply reply);`
- `ICanTell.cs`: `public interface ICanTell<in TMessage> { void Tell(TMessage message); }`, the
  address of an actor (the name previews Akka.NET's own `ICanTell`). `ConnectorActor` now
  implements `ICanTell<ConnectorMessage>`.
- `ConnectorMessage.cs` gains `GetStatus(ReplyTo<ConnectorStatus> ReplyTo)`; `ConnectorStatus.cs`
  is `ConnectorStatus(string ConnectorId, string? ActiveSession)`; `ConnectorActor.Handle` gains
  `case GetStatus get: get.ReplyTo(new ConnectorStatus(ConnectorId, _activeSession));`.
  Commands (`StartSession`, `EndSession`) stay fire-and-forget: their outcome is published.
- `AskExtensions.cs` (37 lines): `AskAsync<TMessage, TReply>(this ICanTell<TMessage> actor,
  Func<ReplyTo<TReply>, TMessage> createMessage, TimeSpan timeout, CancellationToken
  cancellationToken = default)`:
  - `ArgumentOutOfRangeException.ThrowIfLessThanOrEqual(timeout, TimeSpan.Zero)`: zero and
    `Timeout.InfiniteTimeSpan` are refused, so the timeout really is mandatory;
  - `new TaskCompletionSource<TReply>(TaskCreationOptions.RunContinuationsAsynchronously)`, with
    the comment that without it the asker's continuation would run on the actor's loop, inside the
    actor's turn;
  - a linked `CancellationTokenSource` with `CancelAfter(timeout)`; its registration completes the
    task with `TrySetCanceled(cancellationToken)` if the caller cancelled, otherwise with
    `TrySetException(new TimeoutException($"No reply within {timeout}."))`;
  - `actor.Tell(createMessage(answer => reply.TrySetResult(answer)));` and the comment that a late
    reply finds the task completed and is dropped.
- **Call site** (quote this form): `connector.AskAsync((ReplyTo<ConnectorStatus> replyTo) => new
  GetStatus(replyTo), AskTimeout, TestContext.Current.CancellationToken)`. Typing the lambda
  parameter lets C# infer both type arguments; otherwise you must write
  `AskAsync<ConnectorMessage, ConnectorStatus>(...)`.

**Tests** (`ReplyAndAskTests.cs`)

- `Given_a_reply_address_in_a_message_when_told_then_the_reply_goes_there`: the reply address is
  **another mailbox** (`new GetStatus(ReplyTo: statusBoard.Tell)`, where `statusBoard` is a
  `Mailbox<ConnectorStatus>`): a pure tell-only exchange, nobody waits.
- `Given_an_occupied_connector_when_asked_for_its_status_then_it_answers`.
- `Given_a_busy_connector_when_asked_with_a_short_timeout_then_it_times_out`: `authorize` blocks
  on a `ManualResetEventSlim`, so the actor is stuck in a slow token check; a `GetStatus` asked
  with a 100 ms timeout waits behind it and throws `TimeoutException`. (`try/finally` releases the
  token check so disposal can drain.) This is the "why fire-and-forget is the default" test: an
  ask waits for everything ahead of it in the mailbox.
- `Given_any_connector_when_asked_without_a_timeout_then_the_ask_is_refused` (theory: 0 ms and
  -1 ms, i.e. `InfiniteTimeSpan`): `ArgumentOutOfRangeException`.

**Gotcha / finding (C# 14 extension members on RC3)**

I first wrote `AskAsync` as a C# 14 extension block, `extension<TMessage>(ICanTell<TMessage>
actor) { public Task<TReply> AskAsync<TReply>(...) }`, hoping callers could write
`connector.AskAsync<ConnectorStatus>(...)` with `TMessage` inferred from the receiver. On SDK
11.0.100-rc.3 that does **not** bind: `error CS1061: 'ConnectorActor' does not contain a
definition for 'AskAsync' and no accessible extension method 'AskAsync' accepting a first argument
of type 'ConnectorActor' could be found`. A probe showed that once any type argument is explicit,
all of them must be given, the extension's first: `i.Probe1<string, int>()` compiles,
`i.Probe1<int>()` does not; a call with no explicit type arguments infers fine. The block gave no
advantage, so 2.3 uses a classic `this` extension method (which also keeps extension blocks for
3.7). Tell the ch03-s07 writer: do not claim partial explicit type arguments work with generic
extension blocks.

## ch02-s04: Let it crash: supervision and addresses by hand

**Types to quote**

- `ConnectorActor.cs` gains `public Task Completion => _mailbox.Completion;` (completes when the
  actor stops, faults if handling a message threw).
- `Supervisor.cs` (51 lines): `Supervisor(Func<ConnectorActor> createChild) :
  ICanTell<ConnectorMessage>, IAsyncDisposable`.
  - `Tell` forwards to `Volatile.Read(ref _child)`; the doc comment says a message told while the
    child is crashing is lost.
  - `SuperviseAsync` is the "parent loop": `while (true) { try { await _child.Completion; return; }
    catch (Exception exception) { Volatile.Write(ref _child, _createChild());
    ChildRestarted?.Invoke(exception); } }`. A normal completion (disposal) ends the loop.
  - `event Action<Exception>? ChildRestarted`, raised on the supervisor's loop after the
    replacement. Tests use it to wait for the restart deterministically.
  - No restart limit and no backoff: say so, and point to `OneForOneStrategy` and
    `BackoffSupervisor` in 2.8.
- `ActorDirectory.cs` (24 lines): `ActorDirectory<TActor>(Func<string, TActor> createActor)
  where TActor : IAsyncDisposable`, backed by `ConcurrentDictionary<string, Lazy<TActor>>`;
  `GetOrCreate(id) => _actors.GetOrAdd(id, key => new Lazy<TActor>(() => createActor(key))).Value`.
  The comment explains the `Lazy`: `GetOrAdd` may run its factory twice under contention and keep
  one result; with `Lazy` the loser builds a cheap wrapper, never a second running actor. This is
  the "one live instance per identity" of ADR 0001 in miniature.

**Tests** (`SupervisionTests.cs`)

- `Given_an_occupied_connector_when_it_crashes_then_the_restart_forgets_it`: the key test. Session
  A starts; status shows `session-a`. `StartSession("session-b", ...)` is rejected
  (`ConnectorOccupied`) and the subscriber `PublishToFailingBoard` throws
  `InvalidOperationException("The live board is unavailable.")` for every `SessionRejected`. The
  connector crashes, the supervisor restarts it, `ChildRestarted` reports the
  `InvalidOperationException`, and the status is now `ActiveSession == null`: "Session A is still
  charging, but the restarted connector no longer knows about it." This sets up persistence.
- `Given_a_crashed_connector_when_it_has_restarted_then_its_address_works`: a crash on a free
  connector (token `token-blocked` is rejected and the board throws), then `session-b` starts
  through the same `Supervisor` address.
- `Given_a_directory_when_one_id_is_looked_up_twice_then_it_is_one_actor` (and a different id gives
  a different actor).
- `Given_a_directory_when_many_threads_look_up_one_id_then_one_actor_is_created`: 100 parallel
  lookups, the factory runs exactly once.
- `Given_supervised_connectors_in_a_directory_when_used_then_each_has_its_state`:
  `ActorDirectory<Supervisor>` of supervised connectors, two ids, independent state. Quote this
  as the preview of "repository = lookup by identity" and of the shard region (directory +
  supervision + location).

**Surprise worth telling.** My first crash test made the occupied connector call a failing token
service, and it never crashed: an occupied connector rejects *before* it calls the token service.
The crash had to come from code that runs on that path. The lesson the test now carries: anything
an actor calls during its turn, including a subscriber callback, fails inside the actor. (Akka.NET
avoids this for publishing because subscribers receive messages, not callbacks.)

**Gotchas**

- The outline says `BackoffOptions.OnFailure(...)`. In Akka.NET 1.5.73 the factory is the static
  class **`Akka.Pattern.Backoff`**: `Backoff.OnFailure(...)` returns `BackoffOptions`, as
  `research/akka-core.md` already noted. There is no `BackoffOpts`.
- Akka.NET logs each supervised failure at error level with a `Cause:` and the exception chain, so
  the `dotnet test` output of this project shows `FirmwareCatalogUnavailableException ... --->
  System.Net.Http.HttpRequestException: The catalog is down.` and the `ArgumentException` from the
  Resume test even though all tests pass. Readers may think something failed; mention it.
- In OnFailure mode the backoff supervisor stops the failed child and starts a new one after the
  backoff. Messages sent to the supervisor during the backoff are not delivered to a child, which
  is why the restart test retries its final `Ask` inside `AwaitAssertAsync` (200 ms per attempt).

**Gotchas**

- My first attempt to stop the background `dotnet run` with SIGINT did nothing: a process started
  in the background by a non-interactive shell inherits an ignored SIGINT. SIGTERM (what

  Akka research notes say SIGTERM triggers the CLR hook and SIGINT does not; the log above is from
  SIGTERM, and with SIGTERM it is the CLR hook that starts coordinated shutdown, before the host's
  own "Application is shutting down...". The test proves the in-process path (`StopAsync`).
- A typical `ChildActorOf`/`Ask` in a web endpoint: prefer `IRequiredActor<T>.GetAsync(ct)` over
  `.ActorRef`, because it waits until `WithActors` has registered the actor
  (`research/akka-core.md` §6).

## Deviations from the outline (and why)

1. **`ActorDirectory<TActor>` is generic and stores `Lazy<TActor>`** (2.4). The outline says
   `ConcurrentDictionary<string, ConnectorActor>`. `ConcurrentDictionary.GetOrAdd` can run its
   factory twice, which would start two `ConnectorActor` loops for one id; `Lazy` prevents that.
   Generic, so the same directory can hold plain `ConnectorActor`s (tests 3 and 4) or supervised
   ones (`ActorDirectory<Supervisor>`, test 5), which is the better preview of a shard region.
2. **The 2.4 crash comes from a failing event subscriber**, not from a dedicated crash message:
   see the "surprise" under 2.4.
3. **`AskAsync` is a classic extension method**, not a C# 14 extension block (2.3, with the RC3
   finding above).
4. **`Backoff.OnFailure(...)`**, not `BackoffOptions.OnFailure(...)` (2.8): the real 1.5.73 API.
5. **The decider lives in the backoff options** (`WithSupervisorStrategy(new
   OneForOneStrategy(Decide))`) rather than in a separate parent actor's `SupervisorStrategy()`
   override. The outline lists the decider, the backoff supervisor and auto-reset; one place shows
   all three, and the tests show Resume versus Restart.
6. **2.8 adds `BlockingFirmwareLookupActor`** as the `ReceiveAsync` side of the comparison, and a
   `Ping`/`Pong` pair so the tests can see whether a mailbox is running.
7. **2.9 adds a sixth learn project, `learn/Ch02.Hosted.Tests`**, not in sample-architecture §3's
   `learn/` list. The outline puts `ChargerTwin` in a test project (2.6) and asks a separate web
   project to host it (2.9). The web project compiles the twin's files by link (it must not
   reference a test project), and a test project that also referenced `Ch02.AkkaBasics.Tests`
   would see two copies of every type, so the hosted tests needed their own project. They use only
   the ASP.NET Core shared framework and Kestrel on port 0, because
   `Microsoft.AspNetCore.Mvc.Testing` (WebApplicationFactory) arrives in ch12-s11. The editor may
   want §3 updated.
8. **2.9 adds `POST /chargers/{id}/boot-notification`** next to the outlined GET endpoint, so a
   reader can boot the twin from `curl` and see the 503 (stashed question, ask timeout) turn into
   200.
9. **No separate `tests/Directory.Build.props`** at ch02-s01: the outline's "tests/Directory.Build
   .props-style test settings for learn tests" are in `learn/Directory.Build.props`, conditioned on
   project names ending in `.Tests` (sample-architecture §2.3 introduces `tests/Directory.Build
   .props` at ch03-s05).
10. **Tag annotations** follow this chapter's brief and ch01: `"2.1 Shared mutable state:
    double-booking a connector"` (not sample-architecture §10's `"chNN-sMM: <title>"`). Commit
    subjects follow §10 exactly, with the `Book-Section:` trailer plus the harness's
    `Co-Authored-By` and `Claude-Session` trailers.
