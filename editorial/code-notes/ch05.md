## ch05-s03: Keeping the core pure, enforced

**Files:** `build/DomainPurity.targets` (new), `Directory.Build.targets` (the placeholder comment
replaced by an `Import`), `Ohmline.slnx` (`/tests/` gains the project), and
`tests/Ohmline.ArchitectureTests/` (8 new files).

**`Directory.Build.targets`** (4 lines):

```xml
<Project>
  <!-- Build checks that run after every project file has been read. -->
  <Import Project="$(MSBuildThisFileDirectory)build/DomainPurity.targets" />
</Project>
```

**`build/DomainPurity.targets`** (44 lines) — quote lines 11–42:

- `IsOhmlineDomainProject` = `$(MSBuildProjectName.EndsWith('.Domain'))`.
- An item list `ForbiddenDomainPackagePrefix`: `Akka`, `OpenTelemetry`, `Npgsql`,
  `Microsoft.AspNetCore`.
- Target `CheckDomainPurity`, `BeforeTargets="CoreCompile"`, conditioned on the property. It
  builds a case-insensitive regex `(?i)^(Akka|OpenTelemetry|Npgsql|Microsoft.AspNetCore)` from the
  item list, collects `_ImpureReference` from `@(PackageReference)` (regex match, written as a
  property function whose arguments are split over two lines) and from `@(FrameworkReference)`
  equal to `Microsoft.AspNetCore.App`, and raises one `Error` with `Code="OHM0001"`.
- **Real output**, with `Akka`, `akka.hosting`, `Shouldly` and the ASP.NET Core framework
  temporarily added to `Ohmline.Charging.Domain` (not committed):

  ```text
  $ dotnet build src/Charging/Ohmline.Charging.Domain
  .../build/DomainPurity.targets(39,5): error OHM0001: Ohmline.Charging.Domain references Akka, akka.hosting, Microsoft.AspNetCore.App. A domain project must stay pure (section 5.3). Move the code that needs it to an Actors, ReadModels or Api project. [.../Ohmline.Charging.Domain.csproj]
      1 Error(s)
  ```

  Note the case-insensitive match (`akka.hosting`) and that `Shouldly` is not flagged: the target
  blocks infrastructure families, as the outline says, not every package. (Architecture §4 says a
  Domain project may have no packages at all; the reflection test below is the stricter check.)

**`tests/Ohmline.ArchitectureTests`**

- `Ohmline.ArchitectureTests.csproj`: **wildcard** project references,
  `<ProjectReference Include="../../src/**/Ohmline.*.Domain.csproj" />` and the same for
  `*.Contracts.csproj`, so a new context is covered without editing this project. (5.5 adds an
  explicit reference to the shared kernel.)
- `Repository.cs` (`internal static class Repository`): `Root` (walks up from
  `AppContext.BaseDirectory` to the folder with `Ohmline.slnx`), `DomainProjects` and
  `ContractsProjects` (read from `Ohmline.slnx`, names starting `Ohmline.` and ending `.Domain` /
  `.Contracts`), and `Load(string project)` which calls `Assembly.Load` and turns a
  `FileNotFoundException` into "X is in Ohmline.slnx, but Ohmline.ArchitectureTests does not
  reference it".
- `DependencyRules.cs` (`internal static class DependencyRules`): a **C# 15 extension block**,
  `extension(Assembly assembly) { public IEnumerable<string> ReferencedNames => ...; }` (an
  extension *property* over `GetReferencedAssemblies()`), and predicates `IsInfrastructure`
  (the same four prefixes, case-insensitive), `IsRuntime` (a file of that name exists next to
  `System.Private.CoreLib`, i.e. in the `Microsoft.NETCore.App` shared framework), `IsSharedKernel`,
  `IsContracts`. Its summary explains why compiled references and the build target are both
  needed: an unused package never shows up in compiled references.
- Tests (the test names are sentences, not `Given_…_when_…_then_…`; architecture rules have no
  command to name):
  - `DomainPurityTests.A_domain_assembly_references_no_actors_telemetry_database_or_web(project)`
    and `.A_domain_assembly_references_only_kernel_contracts_and_runtime(project)`: theories
    over `Repository.DomainProjects` (4 rows each).
  - `ContractsPurityTests.A_contracts_assembly_references_only_the_shared_kernel_and_runtime(project)`
    (5 rows: Billing, Charging, DriverAccounts, SiteEnergy, Tariffs).
  - `DependencyRulesTests`: `An_actor_telemetry_database_or_web_assembly_is_infrastructure`
    (5 inline rows), `The_runtime_and_Ohmline_assemblies_are_not_infrastructure` (4 rows),
    `A_package_assembly_is_not_part_of_the_runtime` (this test assembly's own reference to
    `Shouldly` is caught), `Every_domain_and_contracts_project_in_the_solution_is_checked`. Its
    summary says it plainly: "The purity tests pass trivially while the domain projects are
    nearly empty. These tests show that the rules would catch a violation".
  - `DomainPurityTargetTests` — **the build target is itself under test**:
    `A_domain_project_that_references_Akka_fails_to_build`,
    `A_domain_project_that_uses_the_ASP_NET_Core_framework_fails_to_build`,
    `A_domain_project_without_infrastructure_builds`, `An_actors_project_may_reference_Akka`.
    `PurityProbe.BuildAsync(projectName, references)` writes a throwaway
    `Ohmline.Probe.Domain.proj` (a plain `<Project>` that imports the real
    `build/DomainPurity.targets` and defines an empty `CoreCompile` target) into a temporary
    folder and runs `dotnet msbuild <proj> -t:CoreCompile -nologo -noAutoResponse -nr:false`.
    No restore, no compile: the four tests take about one second together. The `dotnet` host is
    found from `DOTNET_HOST_PATH`, then `DOTNET_ROOT`, then `PATH`.
- **Mutation-checked:** removing the `Akka` prefix from the targets file makes
  `A_domain_project_that_references_Akka_fails_to_build` fail (`exitCode should not be 0`).

## Surprises and gotchas (for the writer)

- **MSBuild batching stops at the first failing batch.** My first version raised the error with
  `%(_ImpureReference.Identity)` in `Text`; with two forbidden references only the first was
  reported, because the `Error` task fails the target in the first batch. The committed version
  uses `@(_ImpureReference, ', ')` and reports all of them in one error.
- **Property-function arguments may span lines.** `$([System.Text.RegularExpressions.Regex]::IsMatch(`
  newline `'%(Identity)', '$(_Forbidden)'))` works (verified in a scratch project), which is how
  the target stays under 100 characters per line.
- **CPM catches unknown packages first.** Adding a package with no `PackageVersion` (I tried
  `npgsql`) fails restore with `NU1010` before the purity target can run; the demonstration
  above uses packages that are in `Directory.Packages.props`.
- **Static property initializers run in textual order.** Declaring `Repository.ProjectFiles`
  after the properties that use it made every architecture test fail with
  `System.TypeInitializationException : The type initializer for 'Ohmline.ArchitectureTests.Repository' threw an exception. ---- System.ArgumentNullException : Value cannot be null. (Parameter 'source')`.
  Fixed before commit by moving it up.
- **Compiled references only list what the code uses.** An empty `Domain` project references
  only `System.Runtime`, whatever its `.csproj` says. That is why the chapter needs both checks,
  and why the purity tests pass trivially at this point in the book (the `DependencyRulesTests`
  summary says so).
- **`DomainPurityTargetTests` start child `dotnet msbuild` processes.** They need a `dotnet` on
  `PATH` (or `DOTNET_HOST_PATH`/`DOTNET_ROOT`), which any reader running `dotnet test` has.

No errata: nothing from earlier chapters needed fixing.
