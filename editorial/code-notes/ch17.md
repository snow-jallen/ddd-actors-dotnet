## ch17-s06: Stash, persist and the double count

**Files:**

- `TracedPersistentActor.cs` (s06: 117 lines; **quote this tag's `AroundReceive`, lines 35–70**):
  `_handlerInvoked` is set inside a lambda wrapped around `receive` and passed to `base.AroundReceive`;
  afterwards, if a handler ran, `OnMessageHandled(inner, elapsed)`; if not, `ConsumerSpans.Stashed(span,
  _actorType)`. New members: `protected virtual void OnMessageHandled(object message, TimeSpan duration)`
  ("The place to count what an actor processes (Chapter 18)"), `PersistTraced<TEvent>` and
  `PersistAllTraced<TEvent>(events, handler, onComplete)`, and a private `Apply` that records the persist
  span and runs the handler inside an apply span. The class remark explains the double pass.
- `WriteSpans.cs` (new, internal, **quote whole**, 58 lines): `Begin(actorType, persistenceId)` returns
  null unless a span is current (untraced writes record nothing); `_startedAt = DateTimeOffset.UtcNow` at
  the Persist call; `Stored(event, sequenceNr)` starts `persist {EventType}` with `startTime:
  _startedAt`, tags `akka.persistence.id`, `akka.persistence.sequence_nr`, `akka.event.type`, and ends it
  at once (`using var`), so it is never current; `Applying(event)` → `apply {EventType}`;
  `Completing()` → `persisted {ActorType}` (the span around PersistAll's completion callback, where the
  shell replies and the journey carries out its effects). All are `Internal` children of the command's
  `process` span.
- `ConsumerSpans.Stashed`: renames the span `stash {ActorType}` and tags `akka.message.stashed = true`.
- `DeciderActor.Handle` and `ChargingJourneyActor.Hear` call `PersistAllTraced` instead of `PersistAll`.

**Tests:** `tests/Ohmline.Telemetry.Tests/StashAndPersistTests.cs` (a `PersistenceTestKit` with a
`Meter` test actor) — `Given_commands_that_wait_behind_a_write_then_each_is_handled_once` (three traced
commands; the first write held back by a `JournalGate` interceptor until at least two `stash Meter` spans
exist; then exactly three `Read`s handled and three `process Meter` spans),
`Given_a_traced_command_then_its_writes_are_children_of_its_span` (persist/apply/persisted are children
of process; the persist span starts inside the process span and ends after it; the event handler ran in
the apply span and the reply was sent from the persisted span),
`Given_a_plain_command_then_it_is_handled_once_and_records_no_span`.

**Surprises:**

- **The persistence TestKit's journal interceptor is sent to the journal as a message, so with
  `serialize-messages = on` the journal gets a deserialized copy.** A gate held in a field of the
  interceptor never opens (the copy has its own `TaskCompletionSource`); the test's `JournalGate` finds
  its gate by an `Id` in a static dictionary. Symptom: the first write never completed; the two stashed
  commands became dead letters at shutdown.
- `Activity.DisplayName` can be changed after the span started (it is how the stash pass becomes
  `stash Meter`), confirming what the research notes left unverified.
- The research's per-command `TracedCommand<T>` wrapper is not needed: wrapping the `receive` delegate
  that `AroundReceive` hands down detects "a handler ran" for every handler at once.

**What is a parent and what is a link** (for the chapter's map of one charge):

| From | To | Relation |
|---|---|---|
| HTTP request (ASP.NET Core server span) | `process {Actor}` of the asked/told entity | parent |
| `process` span | `persist`, `apply`, `persisted` spans of its write | parent |
| journey's `persisted ChargingJourneyActor` | `process IdTokenActor` / `process SitePowerBudgetActor` (journey's Tells), the charger port's publish | parent |
| projection runner's `process {projectionId}` | the projection's asks (journey relay, session-ended subscriber) | parent |
| stored event's deciding `process` span | `process {projectionId}` (session history, live board, driver app, journey relay, subscriber, integration relay = the feed relay, dispatcher) | **link** |
| WebSocket connection's request span | each `receive ocpp` frame span | **link** |
| the span that started a journey timer | `process ChargingJourneyActor` when it fires | **link** |
| `receive ocpp` | `process ChargerConnectionActor` → its asks → `process ChargePointActor` / `process ChargingSessionActor` | parent |

So "one trace from an OCPP frame to the receipt" is, precisely: frame → connection actor → session
actor → its write (one trace); then, by link, the journey relay's projection span → journey → its effects
(a second trace, tied by `messaging.message.conversation_id` = the journey/session id); Billing's HTTP
calls from the payment port carry the trace in `traceparent` (HttpClient instrumentation); the receipt is
issued by Billing from the feed, which it polls on its own schedule (another trace). Replies do not carry
the trace (ADR 0012), so a journey step triggered by a reply (`TokenLocked`, `PowerAllocated`,
`HoldPlaced`) runs in no span.

**Surprises:**

- **A timer's message is not what `AroundReceive` sees.** Akka.NET 1.5.73 hands `AroundReceive`
  `Akka.Actor.Scheduler.TimerScheduler+TimerMsg` and takes the message out of it only inside
  `base.AroundReceive`, on the way to the handler. A traced timer message was therefore unhandled
  (`LinkTests` timed out waiting for the ring), and at s06 `OnMessageHandled` was given the `TimerMsg`.
  Found with a probe actor whose `AroundReceive` reported `around saw
  Akka.Actor.Scheduler.TimerScheduler+TimerMsg`. Fixed in this section (Errata).
- **`Akka.Persistence.Journal.Tagged` is a struct.** A first `TraceEnvelopeTagger` used
  `.OfType<Tagged>().FirstOrDefault() is { } tagged`, which matches `default(Tagged)` when no tagger tags
  the event; the SQL journal then failed every untagged context's write (the tariff book's first):
  `System.ArgumentNullException: Value cannot be null. (Parameter 'source') at
  Akka.Persistence.Sql.Journal.Dao.ByteArrayJournalSerializer.Serialize(...)`, 19 integration tests red.
  The tagger is a loop with `is Tagged tagged`; its summary says why.
- **A write adapter is chosen by the type of what was persisted**, so the contexts' taggers never see a
  `TraceEnvelope`; without `TracedEventTagger` every traced event would be stored untagged and invisible
  to every projection. Two adapters cannot both be bound to `TraceEnvelope` in one journal, hence one
  composite per host.
- `EventEnvelope(offset, pid, seqNr, event, timestamp)` is obsolete since 1.5.11 (CS0618 as error); the
  constructor with `string[] tags` keeps the tags.
- From this tag the integration and system tests store real trace envelopes in PostgreSQL (the node's
  SDK samples spans with no exporter configured), and pass: the envelope crosses remoting (gateway to
  node) and the journal, and the projections open it.

## Surprises and gotchas (for the writer)

1. ASP.NET Core starts a request activity even with no listener, so traced sending starts at the edge
   as soon as `AskTraced` exists (s04).
2. A command that reaches a persistent actor while it recovers or writes passes `AroundReceive` twice;
   the stash keeps the whole envelope, so the trace survives (s05 found it, s06 handles it).
3. Persist callbacks run when nothing is current; the `persist` span is recorded afterwards from an
   explicit `startTime`, and `apply`/`persisted` spans make the callbacks traceable (s06).
4. Metrics need a reader; tracing does not (s02).
5. A timer's message is wrapped in `TimerMsg` until inside `base.AroundReceive` (s07).
6. `Tagged` is a struct (s07).
7. Write adapters are picked by persisted type; one composite tagger per host (s07).
8. The persistence TestKit interceptor is copied by `serialize-messages` (s06 test).
9. Replies are deliberately not traced: an envelope would break `Ask<T>` (ADR 0012).

## Deviations from the outline (with reasons)

1. **s01: a Tariffs diagnostics class and an ActorShell one were added** beside the five the outline
   names. Both names are durable in `sample-architecture.md` §6 (`Ohmline.Tariffs`,
   `Ohmline.ActorShell`); the shell's spans (process, persist) need a source of their own because the
   shell knows no context.
2. **s01: `CreateMeter(IMeterFactory)` is added to each class** so "Meter via IMeterFactory" has code to
   quote; no instruments are created (Chapter 18 owns them).
3. **s02: "all hosts call AddServiceDefaults"** — Node, DeviceGateway and Billing already did. The
   stand-ins `tools/Ohmline.FakePsp` and `tools/Ohmline.FakeGridOperator` deliberately do not: they play
   third parties ("knows nothing of Ohmline and references none of it"), and a real TallyPay would not
   export into Ohmline's dashboard. The simulator is a console app and stays as it is.
4. **s04: three receivers got a temporary one-line unwrap** (`DeciderActor`, `ChargingJourneyActor`,
   `ChargerConnectionActor`), removed again in s05. Without it s04 is red: the edge sends envelopes from
   the moment it calls `AskTraced` (Surprise 1).
5. **s05: span source.** The consumer and write spans come from `Ohmline.ActorShell`, not from each
   context's source (the shell knows no context); context sources carry projection spans
   (`Ohmline.Charging`) and frame spans (`Ohmline.DeviceGateway`).
6. **s06: the "double count" is fixed for `OnMessageHandled`**, a hook, not for a metric: the metrics
   themselves arrive in `ch18-s01` ("DeciderActor records via hooks"). The stash pass is kept as a
   `stash {ActorType}` span rather than dropped, as the research suggested.
7. **s07: trace parent storage is a write-adapter-plus-envelope design:** the actor persists a
   `TraceEnvelope` (the 17.4 serializer stores it, with the inner event's serializer id, manifest and
   bytes), and the node's `TracedEventTagger` tags it. Akka.NET 1.5.73 has no event metadata, and a write
   adapter runs in the journal actor where no span is current, so the actor must wrap. Only traced
   writes are wrapped; untraced events are stored exactly as before.
8. **s07: the "projection runner and SessionEndedSubscriber" spans** are made once, in the runner, for
   every projection (the subscriber is a projection); the subscriber and the journey relay add the
   conversation id. The OCPP frame span (`FrameSpans`) was added so the trace has a start at the gateway.
9. **s07 also fixes s06's hook and `TracedReceiveActor` for timer messages** (Errata). Quote
   `TracedPersistentActor.cs` from `ch17-s06` for the flag's story and from `ch17-s07` for its final
   shape (`_handled` and `Invoke`).
