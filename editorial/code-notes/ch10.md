## ch10-s05: While the write is in flight: the internal stash

**Files:** `tests/Ohmline.Charging.Actors.Tests/ChargePoints/HeldWrite.cs` and `InFlightWriteTests.cs`.

- `HeldWrite<TEvent> : IJournalInterceptor` (`Akka.Persistence.TestKit`): `InterceptAsync(
  IPersistentRepresentation message)` completes `Reached` and awaits `Released` when
  `message.Payload is TEvent`; other writes pass. Created with `HeldWrite<ConnectorReserved>.Create()`
  and installed with `await Journal.OnWrite.SetInterceptorAsync(slowJournal)`. **It keeps its
  state in a static dictionary keyed by an `Id`** (remarks explain why; see Gotchas).
- The test `Given_a_write_in_flight_when_more_messages_arrive_then_they_wait_in_order`: register
  (`CommandAccepted(1)`), install the interceptor, `Reserve(1, DriversCard)`, wait for `Reached`,
  send `Status()` and `Occupy(1, SomeoneElsesCard)`; `ExpectNoMsgAsync(500 ms)`; `Release()`; then in
  this order: `CommandAccepted(2)`, `ChargePointStatus` (version 2, connector 1 `reserved` for
  `DriversCard`), `CommandRejected` with code `reserved-for-another-token`.

**Verified API (1.5.73):** there is no "pass until released" behaviour. `JournalWriteBehavior` has
`Pass`, `PassWithDelay(TimeSpan)`, the `Fail*`/`Reject*` families (with `If`/`Unless`/`OnType`/
`WithDelay` variants) and `SetInterceptorAsync(IJournalInterceptor)`. The interceptor is called
**once per event** (`IPersistentRepresentation`), not once per `AtomicWrite`.

**Internal stash bound (UNVERIFIED claim in the outline; hedge it):** the reference config sets
`akka.persistence.internal-stash-overflow-strategy = "Akka.Persistence.ThrowExceptionConfigurator,
Akka.Persistence"` (the default throws `StashOverflowException`) and the default mailbox has
`stash-capacity = -1` (unbounded). I could **not** bound the internal stash in 1.5.73: with
`akka.actor.default-mailbox.stash-capacity = 2`, and separately with a per-actor
`Akka.Dispatch.UnboundedDequeBasedMailbox` mailbox with `stash-capacity = 2`, three messages
stashed behind a held write were all handled normally, with no exception. (A plain
`UnboundedMailbox` is refused for a persistent actor: "produced message queue type of
[...UnboundedMessageQueue] does not fulfill requirement for actor class [...ChargePointActor].Must be
a subclass of [Akka.Dispatch.IUnboundedDequeBasedMessageQueueSemantics]".) No test of this was kept.
Say "the internal stash is unbounded by default; the strategy configured for an overflow throws" and
do not claim how to set a bound.

## Surprises and gotchas (for the writer)

1. **`serialize-messages = on` copies the interceptor too.** `Journal.OnWrite.SetInterceptorAsync(x)`
   sends `x` to the journal in a message, so with `serialize-messages` the journal gets a
   Newtonsoft copy: completing a `TaskCompletionSource` inside it does nothing for the test, and the
   first version of the 10.5 test hung (`Reached` never completed although the interceptor printed
   `ConnectorReserved ... 2`). `HeldWrite` therefore keeps its gates in a static dictionary keyed
   by an id the copy carries. The same applies to `FailIf`/`RejectIf` predicates (delegates), which
   is why the 10.6 lab runs without `serialize-messages`.
2. **`serialize-messages = on` serializes Akka.Persistence's internal journal messages with
   Newtonsoft**, events included: `SerializationException: Failed to serialize and deserialize
   payload object [Akka.Persistence.Journal.AsyncWriteJournal+Desequenced]. ... Actor type:
   [Akka.Persistence.Journal.AsyncWriteJournal+Resequencer]` → `Unable to find a constructor to use
   for type Ohmline.SiteEnergy.Domain.Sites.SiteConfiguration ... Path
   'Message.Persistent.Payload.Configuration.SiteId'` (logged "Swallowing exception during message
   send"; the actor test then times out). So before `ch10-s10`, the charge point's events were
   checked by Newtonsoft on that hop, not by `ChargingSerializer`. `ActorTestConfig.With` now adds a
   `NewtonSoftJsonSerializerSetup` with `BoundTypeJsonConverter`, which hands any object whose type
   is bound to another serializer to that serializer. Since `ch10-s10`, every actor test sends its
   events through the manifest serializer on that hop. (The TestKit's memory journal itself stores
   objects; only the SQLite tests write real bytes.)
3. **The test journal is not atomic per batch.** `FailIf(e => e.SequenceNr == 4)` on a three-event
   `PersistAll` (3, 4, 5) left event 3 stored (recovered count 3). `PersistAllAtomicTests` records
   this; the SQL journal's behaviour (whole batch refused) is shown in 10.9.
4. **No `tags` column in tag-table mode.** The outline's "the tags column that stays empty in
   TagTable mode" is wrong for Akka.Persistence.Sql 1.5.73 on SQLite: with `TagMode.TagTable` the
   `journal` table has no `tags` column (`SQLite Error 1: 'no such column: tags'`). Tags live only in
   the `tags` table.
5. **`FrozenDictionary` keeps the last of duplicate keys** when built from a sequence, so a manifest
   used twice would silently win; the reverse registry goes through `ToDictionary` first (which
   throws).
6. **Property order in the JSON is leaf members first, base members last** (`commandId`,
   `occurredAt`, `chargePointId` come at the end). Harmless, but visible in every golden file.
7. **`created` is ticks, not ISO text**, and from the wall clock, not the `TimeProvider`.
8. **An idle node creates no SQLite file;** the journal starts lazily.
9. **CS9107** if a primary-constructor parameter (`output`) is both passed to the TestKit base and
   used in the class: the wrong-branch tests use an explicit constructor and field.
10. **`dotnet test` hung** (no timeout on `TestContext.Current.CancellationToken`) while debugging
    gotcha 1; every wait on a test-owned task now has `Dilated(TimeSpan.FromSeconds(3))`.

## Deviations from the outline (with reasons)

- **10.2 "a protocol union inside the actor":** no separate inbound protocol union type was added;
  nothing in the shell would use it, since Akka's typed `Command<T>` handlers dispatch on the
  closed records. The exhaustive dispatch inside the shell is over the domain's unions: the
  `Result` returned by `Decide` (10.4), `ChargePointError` in `ErrorMapping`, `ChargePointState` and
  `ConnectorState` in `StatusMapping`. `Send` is tested in `Ohmline.ActorShell.Tests` and has no
  production caller yet (the journey in Chapter 15 is the first that holds unions to send).
- **10.2 wrong branch:** there is no production actor at `ch10-s02`, so the mistaken shell is a
  private actor inside the demonstration test.
- **10.3/10.4 test project:** `tests/Ohmline.Charging.Actors.Tests` was created at `ch10-s02` (for
  `ErrorMappingTests`), and `tests/Ohmline.ActorShell.Tests` too (one test project per production
  project with logic). 10.4's "create ... (moving SerializationTests' project setup)" became adding
  the persistence TestKit to the existing project.
- **10.3 registration:** `WithCustomSerializer("charging", ChargingSerializer.BoundTypes, ...)`, where
  `BoundTypes` also lists `ChargePointQuery` and `ChargePointStatus` (queries and their answer are
  wire messages too) and, from 10.10, `SessionCommand` and `SessionEvent`.
- **10.4 "register in Node":** without sharding there was nothing to register, so
  `ChargePointDirectory` (a parent that starts one `ChargePointActor` per id and forwards) is
  registered by `AddChargingContext()` and used by the SQLite tests. Chapter 12 replaces it with the
  shard region; delete it then.
- **10.4 query order:** in `DeciderActor` (10.10) the base class registers `Command<TCommand>`
  before the subclass's query handlers. This is safe because queries never derive from the command
  base; the 10.4 version registers the query first, as the outline says.
- **10.7:** state surviving a restart is shown by `NodeRestartTests`, not by a manual `dotnet run`
  (the Node has no command endpoint before 12.5).
- **10.8:** the outline's `tags` column does not exist (gotcha 4); `docs/journal-tour.md` says so.
- **10.9:** the second writer sends a `ReserveConnector` for connector 1 after the lapse instead of a
  `CancelReservation` for another connector. That produces a two-event batch (3 and 4) and so also
  proves that a SQL journal refuses a whole batch (only 3 collided; 4 is not there), which 10.6
  needs and the test journal cannot show. The first writer reserves connector 2 instead.
- **10.10 replies for Site Energy:** `DeciderActor` lives in `Ohmline.ActorShell`, which may not
  reference any context, so it cannot build Charging's `CommandAccepted`. It has two hooks,
  `Accepted(long)` and `Rejected(TError)` (the outline names only the error hook), and Site Energy
  has its own `BudgetCommandAccepted`/`BudgetCommandRejected` in `Ohmline.SiteEnergy.Contracts`.
  **Editor decision needed before 12.5/12.6:** the outline later says `Ask<CommandReply>` and a
  `DeciderActor` LRU of `CommandId -> CommandReply`; that needs either one reply type in the shared
  kernel (with one serializer for it) or the per-context replies done here.
- **10.10 package:** `Ohmline.ActorShell` references `Akka.Persistence.Hosting` to get
  `Akka.Persistence` (not pinned on its own in §2.4). Ask the editor whether to pin
  `Akka.Persistence` instead.

  AkkaConfigurationBuilder)`; the code uses an extension block with the same call shape.
