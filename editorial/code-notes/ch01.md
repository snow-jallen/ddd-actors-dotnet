## ch01-s04: Consistency without distributed transactions

**File:** `docs/adr/0001-single-writer-per-aggregate.md` (title "0001. One writer per aggregate").

- **Context:** concurrent Ohmline examples (two cards at one connector within a second; five
  sessions at `slc-depot` plus a curtailment; duplicated or reordered meter readings); the costs
  of shared-database locking and of two-phase commit; Helland's entities and activities; Martin
  Thompson's single-writer principle.
- **Decision (quotable bullets):** exactly one live instance per aggregate identity processes its
  commands one at a time; no transaction spans two aggregates (no 2PC, no database transaction
  across two aggregates); cross-aggregate rules are messages between writers tracked by an
  activity (process manager), eventually consistent and idempotent; uniqueness by making the
  unique value an aggregate's identity (the id token). Then one paragraph naming the mechanism:
  persistent actor + mailbox, cluster sharding, journal sequence numbers (Chapters 10 to 12).
- **Consequences:** seven bullets, including the throughput ceiling of a busy site's power budget,
  read models for cross-aggregate questions, and split brain / two clusters as the threat.
- **References:** Helland CIDR 2007 PDF (https://www.cidrdb.org/cidr2007/papers/cidr07p15.pdf,
  HTTP 200), ACM Queue 2016 (https://queue.acm.org/detail.cfm?id=3025012: **returned HTTP 403 to
  curl**, which looks like bot protection; check it in a browser before citing it in Further
  reading), Thompson 2011 (https://mechanical-sympathy.blogspot.com/2011/09/single-writer-principle.html,
  HTTP 200).

### Gotchas

1. **An empty `.slnx` does not build or test.** Restore reports "Unable to find a project to
   restore!" as a warning, `-warnaserror` turns it into an error, and `dotnet test --solution`
   crashes with "Unhandled exception: The solution configuration '|' is invalid." (an empty
   `.slnx` has no build types). See Deviation 1.
2. **MTP mode needs `--solution` or `--project`** (testing.md §2; the README says so).
3. **`dotnet sln add` oddity (SDK rc.3):** in the scratch probe, adding `src/Probe/Probe.csproj`
   and `tests/Probe.Tests/Probe.Tests.csproj` in one call printed "Solution folder 'src' already
   contains a project with the filename 'Probe.csproj'." and saved nothing. With other names
   (`learn/Ch02.ActorsByHand` + `learn/Ch02.ActorsByHand.Tests` in one call, or `src/Alpha` +
   `tests/Beta.Tests`) it worked and created the `/learn/`, `/src/`, `/tests/` folders. A `.slnx`
   is plain XML; if the command misbehaves, edit the file by hand. (Note for the ch02-s01 coder.)
4. `rollForward: latestFeature` lets a reader use any later 11.0 SDK (a later patch or feature
   band) but never 12.0; `allowPrerelease: true` is required while the pin is an RC.
