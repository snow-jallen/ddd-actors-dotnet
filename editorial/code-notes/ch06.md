## ch06-s03: Money, currency and rounding

**Files** (`src/Ohmline.SharedKernel/Monetary/`)

- `Currency.cs`: `readonly record struct Currency : IValueObject<Currency, string>`; `Code`
  guarded by `IsIsoCode` (`code is { Length: 3 } && code.All(char.IsAsciiLetterUpper)`, no regex);
  statics `Usd`, `Eur`; `TryCreate` returns `Missing` for blank input, trims and upper-cases, then
  `Malformed(..., "an ISO 4217 code such as USD")`. The class summary states the rule used by
  every text value object from here on: **the constructor takes the canonical form, `TryCreate`
  also accepts what people type and returns the canonical form.**
- `CurrencyMismatch.cs`: `sealed record CurrencyMismatch(Currency Left, Currency Right)` with
  `Message` "Cannot combine USD with EUR: convert one of them first."

  corrections) and a guarded `Currency` (a default currency throws). Interfaces:
  `IAdditionOperators`, `ISubtractionOperators`, `IMultiplyOperators<Money, decimal, Money>`,
  `IComparisonOperators`. **No `IAdditiveIdentity`**: the summary says why ("There is no zero
  without a currency"); `Money.Zero(Currency)` is a method. Quotable pair (lines 36–45):
  `TryAdd(Money other)` returns `Result<Money, CurrencyMismatch>`; `operator +` and `-` call the
  private `CommonCurrency`, which throws `InvalidOperationException` with the mismatch's message.
  `operator *(Money, decimal)` never rounds ("such as a price per kWh by the energy").
- `RoundingPolicy.cs` (50 lines): `readonly record struct RoundingPolicy(int decimals,
  MidpointRounding mode)` with guarded `Decimals` (0 to 28) and `Mode` (`Enum.IsDefined`),
  `static Cents` (2 decimals, `AwayFromZero`), `TryCreate(int, MidpointRounding)` as a tuple
  switch, and `Round(Money) => money with { Amount = decimal.Round(money.Amount, Decimals, Mode) }`.
  The summary is the "implicit concept made explicit" sentence: "a tariff names its policy for its
  currency, and nothing else in Ohmline calls Math.Round on money".

called with null**: probe output `Equals(null,null)=True calls=[<null>,<null>]`,
`Equals(a,null)=False calls=[a,<null>]`, `GetHashCode(null)=0 calls=[<null>]`. Hence `?.Id`;
`connector => connector.Id` fails the build with

## Deviations from the outline (and why)

1. **`SharedKernel/Monetary`, not `SharedKernel/Money`** (6.3). A namespace
   `Ohmline.SharedKernel.Money` containing a type `Money` breaks every caller whose own namespace
   is under `Ohmline.SharedKernel` (the kernel's tests): verified with a probe,
   `error CS0118: 'Money' is a namespace but is used like a type`. Architecture §1 says namespaces
   follow folders, so the folder is `Monetary` too.
2. **`CurrencyMismatch`** (6.3) is an extra type: the error of `Money.TryAdd`. It is a single
   record, not part of `ValidationError` (nothing about the raw input is invalid).
3. **`Money` and `RoundingPolicy` do not implement `IValueObject`** (6.3): each has two raw values
   and the interface wraps one. Both have guarded `init`s; `RoundingPolicy` has a `TryCreate`.
   Architecture §5.2 says value objects implement `IValueObject`; the composite ones cannot.
4. **`Voltage × Current = Power`** (6.1) is added to the outline's two extension operators, so
   `Current` and `Voltage` take part in dimensional analysis, and 6.2's Bind chain uses it.
5. **Units name their amount** (`KilowattHours`, `Kilowatts`, `Amperes`, `Volts`) and implement
   `IValueObject.Value` explicitly (6.2). The outline does not name the property; `energy.Value`
   would reintroduce the "which unit?" question the section is about.
6. **`SiteId` is stricter than "lower-case kebab case"**: it requires a three-letter area code
   (`^[a-z]{3}(-[a-z0-9]+)+$`), the shape `docs/acl/assettrack.md` rule 2 already demanded.
   `docs/naming-rules.md` updated in 6.4 (fix-forward; note in `errata.md`).
7. **`ConnectorState` placeholder** (6.6): the outline says "Status placeholder". I named the
   property `State` and the type `ConnectorState`, the glossary's name (Connector status →
   `ConnectorState`) and the type 7.3 turns into a union, so 7.3 replaces one file's content
   instead of renaming a property across the aggregate.
8. **Site Energy domain types are three files** (6.7): `SiteConfiguration.cs`,
   `ConnectorConfiguration.cs`, `PriorityClass.cs`, per the house rule (one type per file; a closed
   hierarchy in a file named after its base). The outline lists them all under
   `SiteConfiguration.cs`. **7.8 should reuse `Sites/PriorityClass.cs`** rather than add a second
   `PriorityClass` under `Budgets/`.
9. **`tests/Ohmline.SiteEnergy.Domain.Tests` is created in 6.7**, not 7.8: the new domain types
   need tests in the same commit (architecture §11). 7.8 adds to it.
10. **`ConfiguredCapacity`, not `EffectiveCapacity`**, on `SiteConfiguration`: the glossary
    defines effective capacity as limit minus curtailment minus margin, "computed in
    `SitePowerBudget`". A configuration has no curtailment, so it gets a different name; the doc
    comment points to 7.8. The ACL's rule enum keeps the document's name `EffectiveCapacity`.
11. **Extra ACL types**: `AssetTrackRow`, `AssetTrackRule`, `SiteSettings`, `AssetTrackImport`
    (plus two private nested records). The outline names the reader, the translator and the union;
    these give the union's cases something to carry and make the document's rule numbers testable.
12. **The CSV reader throws `FormatException`** for a wrong header or an unsplittable line. Those
    mean the file is not an AssetTrack export; every *row* of a real export still gets exactly
    one of the three outcomes.
13. **Property-test names are sentences** (`Adding_energy_is_associative`), like Chapter 5's
    architecture tests: a property has no command. Every other new test follows
    `Given_…_when_…_then_…` (some omit `when` where there is no action, as earlier chapters did).
14. **Demo file `Units/UnitCompileErrors.cs`** (6.1) follows Chapter 3's `#if DEMO_COMPILE_ERRORS`
    convention; not in the outline.
15. **Tag annotations** use `6.N <title>` like Chapters 2–5; commit subjects use `chNN-sMM: <title>`
    with the `Book-Section:` trailer.

## Surprises and gotchas (for the writer)

- **`[InlineData]` cannot carry decimals, and doubles lie.** My first `RoundingPolicyTests` used
  `[InlineData(8.285, 8.29)]`; the test runner showed `amount: 8.285000000000000142108547152,
  rounded: 8.289999999999999147348717088`, and four rows failed. The committed test uses
  `TheoryData<decimal, decimal>` with `[MemberData]`, and its comment says why. Worth a sentence
  in any section with money in theory data.
- **`TryFindSystemTimeZoneById` is case-sensitive on Linux**, except that it looked
  case-insensitive in my first probe: after `TimeZoneInfo.GetSystemTimeZones()` had filled the
  cache, `america/denver` was found as `America/Denver`. In a fresh process, `america/denver`,
  `america/boise` and `AMERICA/DENVER` all return `False`. The translator therefore searches
  `GetSystemTimeZones()` case-insensitively first (comment in `ReadTimeZone`). `US/Mountain` is a
  real IANA link (`HasIanaId` true) and would be accepted on its own; the alias table maps it to
  `America/Denver` first, as the document asks.
- **`EqualityComparer<T>.Create(keySelector)` calls the selector with null** (details under 6.6).
- **Shouldly's `ShouldBeLessThanOrEqualTo` needs `IComparable<T>`**: on `Energy` it fails with
  `error CS0315: The type 'Ohmline.SharedKernel.Units.Energy' cannot be used as type parameter 'T'
  … There is no boxing conversion from 'Ohmline.SharedKernel.Units.Energy' to
  'System.IComparable<Ohmline.SharedKernel.Units.Energy>'.` The units implement
  `IComparisonOperators` (operators), not `IComparable<T>`; the property tests compare
  `.KilowattHours`. I did not widen the kernel's API in a test-only section.
- **`IValueObject.Create` needed no change** when `ValidationError` became a union: the union's
  computed `Message` property keeps `err.Error.Message` compiling (flagged as a risk in the ch03
  notes, deviation 5).
- **Union with a body**: both `ValidationError` (a `Message` property) and `AssetRowTranslation`
  (a `Row` property) compile with a switch over `this` and a `null` arm. Instance fields would not
  (CS9373, research note §2.1).
- **`Match` with union return types**: I avoided `result.Match(...)` where the two lambdas return
  different case types (`Ok<T>` and `Err<Rejection>`), because inference would need an explicit
  type argument, and explicit type arguments on the extension block must name all three (ch03
  gotcha). The ACL uses switch expressions over `Ok<T>`/`Err<E>` there instead.
- **`GetSystemTimeZones()` and determinism**: the translator reads the OS time zone database. It
  is deterministic data, not a clock, but it is the one thing the "pure" translator asks of the
  platform; the lower-case test is skipped off Linux for that reason.
- **The Chapter 2 hosted-test race** (`errata.md`) did not occur in any run during this chapter.
