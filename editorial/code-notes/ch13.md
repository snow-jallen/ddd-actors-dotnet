## 13.1 (no tag): the pipeline, for the diagram

Participants as named in code, in order: `ChargePointActor` (or any `DeciderActor`) →
`Journal` (Akka.Persistence.Sql; tables `journal` and `tags`, written in the same plugin call) →
`SqlReadJournal` (`EventsByTag`, polling) → `ProjectionRunner` (one per projection stream, inside a
`ProjectionDaemon`) → `SessionHistoryProjection` / `SiteLiveBoardProjection` → PostgreSQL schema
`read_models` (`session_history`, `site_live_board`, `projection_offsets`) → query endpoints in
`Charging.Api` (`GET /tokens/{uid}/sessions`, `GET /sites/{id}/live-board`). The three places
latency and failure live: the read journal's polling (lag, tuned in 14.3), the runner and its
projection (restarts, poison events, 13.7), the query (reads the read model, never an aggregate).
Read-your-writes from the entity: `GET /charge-points/{id}` asks the aggregate (since `ch12-s05`).

In PostgreSQL both sides live in one database, `ohmline`: the journal tables in `public`, the read
models in `read_models` (ADR 0009, architecture §6). The SQLite development node has no read side
(see 13.6).

## ch13-s05: Idempotent read models: upserts and the offset in one transaction

**The story is in two diffs:**

- `git diff ch13-s04 ch13-s05 -- src/Charging/Ohmline.Charging.ReadModels/Projections/ProjectionRunner.cs`:
  `SaveAsync(_stream, offset, transaction, ...)` moves inside the transaction, before `CommitAsync`;
  the remarks become "The projection's rows and the offset are written in one transaction (section
  13.5): a crash undoes both, and the event comes again. The projection may still see an event

  delivery is at least once."

  transaction, the one the projection wrote its rows in, so that the rows and the offset are

  and now expects `[1, 2, 3]` ("One transaction (section 13.5): the crash rolled back offset 2's

## Surprises and gotchas (for the writer)

1. **`WithJournal(string journalId, ...)` is obsolete in Akka.Persistence.Hosting 1.5.73** and
   `-warnaserror` fails on it: `error CS0618: 'AkkaPersistenceHostingExtensions.WithJournal(
   AkkaConfigurationBuilder, string, Action<AkkaPersistenceJournalBuilder>)' is obsolete: 'Use
   WithJournal(journalOptions, configureBuilder) instead to combine options configuration with event
   adapters and health checks. This method will be removed in v1.6.'` Event adapters are added
   through the journal builder passed to `WithSqlPersistence(journalBuilder: ...)`, i.e. where the
   host configures the journal. Hence the contexts' `AddChargingTagger()`/`AddSiteEnergyTagger()`
   journal-builder extensions.
2. **The five-argument `EventEnvelope` constructor is obsolete:** `error CS0618:
   'EventEnvelope.EventEnvelope(Offset, string, long, object, long)' is obsolete: 'For binary
   compatibility with previous releases. Since 1.5.11'`. Tests build envelopes with the six-argument
   one that takes the tags.
3. **The stream's completion fails with an `AggregateException`** around the cause (seen as
   "should throw ProjectionStoppedException but threw System.AggregateException"). The runner
   unwraps it (`Unwrapped`) so `RunningProjection.Completion` fails with the cause.
4. **A kill switch alone does not stop the next element.** The first version of "stop" called
   `_killSwitch.Abort(...)` and returned normally; `SelectAsync(1)` then handled offset 3 before the
   abort arrived, stored offset 3, and event 2 was skipped for good (the stop test failed with
   "should be [1L] but was [1L, 3L]"). The fix: abort *and* fail the element
   (`Task.FromException<long>(Stop(...))`). Then the restart that the failure schedules is cancelled
   by the abort, and no later event is handled. Worth a sentence: stopping a stream "at" an element
   needs both.
5. **CS8509 with `ConnectorEvent x and (A or B or ...)`:** the compiler did not see that pattern
   cover the five cases, and the closed-hierarchy switch failed with `error CS8509: The switch
   expression does not handle all possible values of its input type (it is not exhaustive). For
   example, the pattern '_' is not covered.` One arm per event type compiles, and keeps a new
   connector event a build error.
6. **`Persistence` namespace clash in tests:** after `ch13-s02` added
   `Ohmline.Charging.Actors.Tests.Persistence`, `Persistence.Instance` inside that test assembly
   resolved to the namespace (`error CS0234: The type or namespace name 'Instance' does not exist
   in the namespace 'Ohmline.Charging.Actors.Tests.Persistence'`); written
   `Akka.Persistence.Persistence.Instance` in the listing test fix.
7. **Npgsql and `timestamptz`:** the session history writes `StartedAt`/`EndedAt` with
   `.ToUniversalTime()`, because Npgsql 6+ accepts only offset-0 `DateTimeOffset` for `timestamptz`
   and events carry the decision clock's offset (the serializer samples use -07:00). Done
   preventively; the error itself was not provoked.
8. **PostgreSQL `CREATE ... IF NOT EXISTS` is not safe when sessions race** (the ch12 gotcha 14
   error). `ReadModelSchema.EnsureAsync` takes `pg_advisory_xact_lock(hashtext(
   'ohmline.read_models'))` first; three daemons ensure it at once on every node start.
9. **Two extra log lines per failure:** besides the runner's own ERROR, Akka.Streams logs
   `An exception occured inside SelectAsync while executing Task. Supervision strategy: Stop`
   (ERROR, its spelling) and `Restarting graph due to failure.` (WARNING) with the cause.
10. **Explicit interface implementation keeps the persisted shape.** System.Text.Json writes public
    properties only, so `ISiteAllocationEvent` on Site Energy's events changed no golden file.
11. **CS0411 from a transitive `Match` extension** in `Ohmline.IntegrationTests`
    (`ListExtensions.Match<A, B>(IEnumerable<A>, Func<B>, Func<Seq<A>, B>)`, from a package the
    node pulls in): calling `ConnectorId.TryCreate(...).Match(...)` there was ambiguous; the test
    constructs the id directly. Not relevant to the book's listings.
12. **Daemons in the SQLite development node:** none. The read side runs only with
    `ConnectionStrings:ohmline` (PostgreSQL), i.e. under Aspire or the integration tests.

## Deviations from the outline (with reasons)

- **13.2:** the taggers are registered through journal-builder extensions that each context
  provides (`AddChargingTagger()`, `AddSiteEnergyTagger()`) and the host passes to
  `WithSqlPersistence(journalBuilder: ...)`, not inside `AddChargingContext()`/`AddSiteEnergyContext()`:
  the only way to reach the journal from there is the obsolete `WithJournal(string, ...)` (Gotcha
  1). Each event gets exactly one tag; session events are tagged `charging-session` only, not also
  `charging`, so a projection reading both (14.6's driver app) never sees an event twice. The tag
  names live in each context's Contracts (`ChargingTags`, `SiteEnergyTags`), because read models
  may not reference the Actors projects.
- **13.3:** `ReadJournalAccess` is a C# 14 extension property (`system.ReadJournal`) rather than a
  method. The tests use their own `JournalNode` (the shape of the actor tests' internal
  `SqliteNode`).
- **13.4:** `Npgsql` 10.0.3 was already in CPM since `ch12-s10` (the node needed the driver), so no
  `PackageVersion` arrives here. `read_models.projection_offsets` has an extra `tag` column, primary
  key `(projection_id, tag)`: a projection may read several tags (13.8), each with its own offset
  (`ProjectionStream`). The runner depends on `IEventsByTagQuery` (14.7 can pass an in-memory read
  journal) and on an `IOffsetStore` interface (the crash test's decorator). The crash is injected
  by a test offset store; the wrong branch's demonstration uses a projection that fails once after
  the offset was stored, because there the crash between the two writes falls after the offset.
- **13.5:** `session_history` has one more column than listed, `meter_start_wh`, to compute the
  energy so far from each meter value; `Apply` takes the sequence number as a third argument
  (`Apply(row, event, sequenceNr)`), which becomes `last_sequence_nr`. The projection also skips an
  envelope at or below the row's version before applying (the SQL guard remains the real one).
- **13.6:** `numberOfInstances` is one per projection **stream** (three at `ch13-s08`), not per
  projection. Each `ProjectionDaemon` ensures the schema itself (retrying every 5 s) before starting
  its runner. The node adds the read side only with PostgreSQL.
- **13.7:** "max restarts" is counted per event (`MaxRetries` of the policy), not with
  `RestartSettings.WithMaxRestarts`, so that a database outage (an `NpgsqlException` with
  `IsTransient`) never counts against an event and never stops a projection. The status endpoint
  also returns `tag`, `failures` and `updatedAt`; streams are listed from their first start
  (offset 0). A runbook was added.
- **13.8:** Charging's read model may not reference Site Energy's domain (§4,
  `ContextBoundaryTests`), so Site Energy publishes `ISiteAllocationEvent` and `ConnectorAllocation`
  in its Contracts and its four allocation events implement them explicitly; the board matches on
  the interface. The table's columns (`connector_id` key, two sequence guards, `allocated_kw` null/0)
  are the coder's design. `GET /sites/{id}/live-board` returns 404 when the board has no connector
  for the site; `GET /tokens/{uid}/sessions` returns the newest 50 (200 with `[]` when none).
