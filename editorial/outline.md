## 0. Decisions this outline makes

### 0.1 The running domain: Ohmline, a public EV-charging network

All three proposals independently chose EV charging. This outline merges the best parts of each:

- **From Proposal C:** the name *Ohmline*, the ChargePoint aggregate with connector entities, the learning journey (actors by hand, then learning tests), and the "Connector rename" idea for evolving events.
- **From Proposal A:** the site power budget, grid curtailment, the fair-share allocator as the Highlighted Core, the legacy-registry Big Ball of Mud, the ChargingJourney process manager, the depth of the DDD canon, and the separate telemetry and operations chapters.
- **From Proposal B:** the production realism: domain-purity build checks, `tools/verify-tags.sh`, deliberately broken side branches, hand-rolled golden files instead of Verify, a migrator, and reconnection storms during rolling updates.

**Ohmline** is a fictional charge point operator with about 300 sites: public car parks, workplaces and one bus depot. Each site has several charge points from different vendors. Drivers authorize with an RFID card or the driver app. Ohmline has three obligations:

- keep each site within its grid-connection limit, less any curtailment the grid operator has asked for;
- price each session from the tariff that was locked when the session started;
- take payment as a pre-authorization hold that is later captured or voided.

**Why this domain**

- **Invariants are real and quantitative:**
  - a connector hosts at most one session;
  - a reserved connector accepts only the token holder until the reservation expires;
  - meter registers never go backwards;
  - the tariff is locked at the start of a session, and a spend cap stops the session;
  - at each site, the sum of allocations must not exceed the grid limit minus curtailment minus the safety margin, and each allocation must stay within the connector's minimum and maximum.
- **Time is everywhere:** reservations expire, idle fees start after a grace period, time-of-use bands are in site-local time (including DST changes), heartbeats time out, and payment holds expire.
- **Devices are actors by nature:** charge points are long-lived, connected and driven by timers. Sessions, sites and tokens are each a natural single writer.
- **There are several kinds of external system, each a different ACL case:** charger protocol frames, a payment provider with an ugly API, grid demand-response signals, a legacy CSV registry and a roaming hub.
- **There is a real edge client:** drivers use a phone in underground car parks with no signal, which makes offline commands, idempotency and eventual consistency concrete.

**Everything is fictional:** Ohmline, TallyPay (the payment provider), Northgate Grid (the grid operator), AssetTrack (the legacy registry) and every vendor. The charger protocol is a **clearly labeled simplified subset in the style of OCPP 1.6J**, and the book never claims conformance.

### 0.3 House style for code

The full rules are in `sample-architecture.md`. In short:

- **`closed record` hierarchies with `sealed` leaves** for anything that crosses an actor boundary, is persisted, or goes on the wire: commands, events, replies, queries, snapshots and integration events.
- **C# 15 `union`s** for everything that stays in process:
  - aggregate state, decisions, error sets, `Result<T,E>`, effects, parse and translation results, and the actor-side protocol union used for exhaustive dispatch;
  - **process-manager inputs drawn from several contexts**, which share no base type. This is where unions are at their best;
  - on the phone: screen state, command status and send outcomes.
- **A union is never told, asked, replied with or persisted.** The typed `Send` extension member unwraps `.Value`. The reasons:
  - Akka delivers the boxed union struct, not the case inside it;
  - Akka 1.5's Newtonsoft serializer silently restores `Value == null`.
- **Build settings:** CS8509 and CS8655 are errors. Every switch that a `default(union)` can reach has a `null =>` arm.
- **A System.Text.Json `SerializerWithStringManifest`** with permanent manifests and serializer IDs is in place **before the first persisted event** (ch10-s03).
- **Deciders persist with `PersistAll`**, never `PersistAsync` (ch10-s06).
- **Time comes from `TimeProvider`** through a `DecisionContext`. IDs are `Guid.CreateVersion7(clock.GetUtcNow())`. Evolve never reads a clock.
- **The client contracts** (`Ohmline.Charging.Client.Contracts`) are plain DTOs with primitive fields and a source-generated `JsonSerializerContext`; the phone never references `Ohmline.SharedKernel`, a `*.Domain` project or Akka (ch19-s02).

- **C. Anti-pattern catalog.** One page per anti-pattern, each pointing to the chapter that cures it and to its `wrong/*` branch where one exists:
  - anemic actor and logic in Receive
  - one actor per database row
  - Ask chains
  - `IActorRef` used as identity
  - dual writes
  - mutable messages
  - persisting or telling a union wrapper
  - the default Newtonsoft serializer in the journal
  - `PersistAsync` in a decider shell
  - changing `maxNumberOfShards`, PersistenceId formats or serializer IDs
  - `Context.Stop(Self)` or PoisonPill in sharded or persistent actors
  - non-deterministic Evolve
  - editing journal rows to fix a poison event
  - saving a projection offset before the read-model write
  - feature flags evaluated during replay
  - high-cardinality metric tags
  - using the in-memory journal, which hides serialization bugs
  - a god supervisor
  - shipping aggregates (or the Shared Kernel) to the phone
  - trusting client-side validation as an invariant
  - sending a command from the phone before it is stored in the outbox
- **D. Akka.NET configuration defaults cheat sheet.**
  - Split-brain resolver: `keep-majority`, `stable-after = 20s`, `down-all-when-unstable`.
  - Passivation: 120 s.
  - `ask-timeout`: infinite.
  - `state-store-mode`: `persistence`, but always set it to `ddata`.
  - `app-version = assembly-version`.
  - Coordinated-shutdown phases and their timeouts.
  - Persistence: `max-concurrent-recoveries = 50`, `recovery-event-timeout = 30s`, journal circuit breaker (`max-failures = 10`, `call-timeout = 10s`, `reset-timeout = 30s`), snapshot-store circuit breaker (5, 20 s, 60 s), replay filter `repair-by-discard-old`, internal stash overflow strategy (throw).
  - Akka.Persistence.Sql: `tag-write-mode = TagTable`, `batch-size = 100`, `replay-batch-size = 1000`, `use-writer-uuid-column = true`.
  - Persistence Query `refresh-interval` and `query-delay`.
